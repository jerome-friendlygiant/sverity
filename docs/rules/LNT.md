# LNT - Semantic, structural and synthesizability lint

The table supplies the lint titles shown by the CLI and reports. The specification bullets below define the contract each rule is tested against
(`tests/fixtures/<RULE-ID>/`: good, bad, boundary, hierarchy/unknown cases). Rules marked *slang* map slang's own diagnostics (by option name
or error code, see `src/frontend/slang_rule_map.cpp`); nothing slang reports is dropped. A rule with a `gap` in `catalog.json` is Partial; gaps are not repeated here.
The catalog declares obligation IDs. The **Obligation** bullets explain when they apply, and the [lint gate](LINT_WORKFLOW.md#scope-and-gate) defines how they count.

## Specification

Slang-backed rules (named below as slang options or codes) are slang's own diagnostics, converted in `src/frontend/frontend.cpp`: severity copied (Note INFO, Warning WARNING, Error ERROR, Fatal FATAL), confidence Established, `hierarchy` taken from the slang symbol, evidence kinds `macro_expansion`, `slang_note` and `occurrence_list_incomplete`, no `signals`. An option name is mapped in `src/frontend/slang_rule_map.cpp`; an error without option name by its diagnostic code (`ruleForSlangDiag`). An option no rule maps is reported as `SLANG-<option>` at slang's severity, except slang's style and redundancy options, which synthesis builds as written (`case-redundant-default`, `useless-cast`, `ignored-macro-paste`, `bitwise-op-parentheses`, `logical-op-parentheses`): INFO, with `upstream_severity` kept ([severity policy](LINT_WORKFLOW.md#severity-policy)). A slang-backed rule whose Unknown clause reads "decided by slang" still cannot check a construct whose operands do not elaborate (an unknown module or interface): slang reports that as an error, LNT-001 adds its FATAL summary and elaboration coverage is INCOMPLETE, so the run never looks clean. slang's default errors for proven hardware defects (`index-oob`, `range-oob`, `range-width-oob`, `multiple-cont-assigns`, `multiple-always-assigns`, `mixed-var-assigns`, `duplicate-definition`, `redefinition*`, `bad-procedural-force`, `implicit-port-type-mismatch`) stay ERROR when a `-W` option, `--compat` or a source pragma lowers them to warnings; slang's other default errors stay ERROR too unless `--compat` is given. Options that turn diagnostics off or relax the language (`-Wno-*`, `--relax-*`, `--allow-*`, `--translate-off-format`, `--ignore-directive`, ...) mark `upstream-diagnostics` INCOMPLETE.

An AST rule's finding (reported through `Lint::report`) is located at the use site of its construct. A construct written in a macro body is reported at the outermost macro call, so two calls are two findings; the body's location is kept as evidence `macro_definition`. A macro argument is user text and gets no such evidence. A use site in a library unit is not user code, so the finding is dropped, whatever file defines the macro. A construct is inside a final block when its procedure is one, so a macro that writes a final block and an always block marks only the final's body.

### LNT-001
- **Trigger:** slang diagnostics without an option name whose code is not mapped to another LNT rule (syntax, preprocess and other elaboration errors); load failures and internal failures while loading; the summary finding when the design has at least one slang error.
- **Exempt:** slang's too-many-errors fatal is not counted as a design error in the summary (it is still reported, and marks `upstream-diagnostics` INCOMPLETE); mapped diagnostics are reported under their own rule.
- **Severity:** FATAL for load failures, internal failures and the elaboration-error summary; slang's severity (ERROR, FATAL) for each unmapped diagnostic, Established.
- **Unknown:** none: decided by slang. A design with elaboration errors sets upstream-backed rules to Partial (`degradedReason`).

- **Severity:** slang's severity, Established.
- **Unknown:** none: decided by slang.

### LNT-004
- **Trigger:** slang options width-trunc, width-expand, port-width-trunc, port-width-expand; arith-op-mismatch and bitwise-op-mismatch when the two operands are integral types of different width (also when they differ in both width and signedness).
- **Exempt:** explicit casts (slang does not warn on them); and, where the value range (ANALYSIS.md, Value ranges) shows nothing is lost: (a) an arith-op-mismatch of `+`, `-` or `*` with exactly one constant operand, whose result lies in the width of its own expression (a narrow index times a parameter, a 16-bit value times a parameter at 32 bits); (a2) an arith-op-mismatch where one operand is a single unsigned bit and both reach the operation's type unchanged: a flag or an increment (`count + en`); (a3) an arith-op-mismatch or bitwise-op-mismatch whose narrower operand is a fill literal (`'0`, `'1`) or a conditional of fill literals, which takes the context's width; (b) a width-expand on an arm of a conditional that is `+`, `-`, `*` or `<<` and is evaluated at the width of its context (`s ? a * b : '0` into a wider target), whose result lies in that width. (c) a width-expand (or port-width-expand) that is an extension proven to carry the value: a zero extension of an unsigned operand, a sign extension of a signed operand into a signed type, or an extension of a signed operand whose range holds no negative value into an unsigned one, where the operand itself is clean (no operation inside it wraps, no implicit conversion inside it changes a value; an explicit size cast is the author's). A sign extension that an outer conversion then reads as unsigned (also through the arms of a conditional) is proven only by a range without negative values.
- **Severity:** slang's severity (WARNING), Established. A finding meeting (a), (a2), (a3), (b) or (c) is INFO, Established: the message keeps slang's text and adds the proof, recorded as evidence `value_preserved`. Every other shape stays WARNING, including one where the proof is missing; a finding inside a definition no instance of the design uses is INFO as for LNT-005.
- **Unknown:** none: decided by slang and by the AST shape above.
- **Limits:** the trigger is slang's warning set. A constant whose value is known is not judged by its value: a negative constant read by an unsigned target (`localparam signed [7:0] N = -5; assign y16 = N;`) changes the value but is outside the trigger, because slang does not warn on it and a new site would also flag the `-1` idiom for all ones.

### LNT-005
- **Trigger:** slang options implicit-conv, packed-array-conv, sign-conversion, sign-compare, ineffective-sign, case-type (case items and inside sets whose types differ); arith-op-mismatch and bitwise-op-mismatch in every other case: same width with another signedness or type (an enum against a plain vector), or types that cannot be read.
- **Exempt:** explicit casts; and a sign-compare, sign-conversion or same-width arithmetic mismatch whose value is proven preserved at its site, by the value range (ANALYSIS.md, Value ranges) of V1 and V2 or by V3, V4:
  - V1: a sign-compare, or an arith/bitwise mismatch between plain integer or vector types (not an enum, struct or union), where each operand lies, through every implicit conversion layer around it, in the type it becomes: a constant or parameter of known value, a `for` loop variable (its stop test included, where it also takes the value that ends the loop), a narrow unsigned operand, a size cast of such a value, and arithmetic of these that does not wrap.
  - V2: a sign-conversion whose operand lies in the type it is converted to; casts of that type's own width in between only reinterpret the bits, so `3'(i)` converted to 3 unsigned bits carries `i` when `i` lies in 0..7. A concatenation or replication operand is never proven this way.
  - V3: an equality (`==`, `!=`, `===`, `!==`, `==?`, `!=?`) of two operands of one width: it compares bit patterns, whatever their signedness.
  - V4: a sign-conversion from an unsigned concatenation `{a[W-1], a}` or `{{K{a[W-1]}}, a}`, with `a` a signed integral variable of width W and `a[W-1]` a constant select equal to its declared most significant index, converted to a signed type of width W+K, with no other operation between.
  - V5: a sign-conversion from a concatenation whose most significant operand is the constant zero (`{1'b0, limit}` into a signed 9-bit): the value is the unsigned value of the rest, and the range of the whole decides. A first operand that is not a constant zero (`{x, limit}`, `{1'b1, limit}`) proves nothing.
  - V5: a packed-array-conv into a packed array of an enum from a concatenation or replication every piece of which is a value of that enum, laid end to end over the array's width (`{N{ENUM_VALUE}}`): each element is an enumerator.
  - V6: slang types an arithmetic operand in the comparison's or operation's own type before it reports (`l >= (N - 2)` shows two unsigned sides). Such a site is proven when every side that could have been retyped has a value range inside the lower half of its type, where the signed and the unsigned reading agree, and every plain operand reaches the common type unchanged. `(D - 8)` with D = 6 is -2, read as 4294967294, and stays WARNING. An enumerator or a constant of an enum type is a number, so V1 applies to it. The proofs read package functions and parameters, the initializers of an enum's values, the conditions and case items of generate blocks, including a block that is not elaborated (the condition was evaluated), and the parameter overrides of every child instance (`.Width(NumShares * Width)`), also where slang shares one analysed body between instances with equal parameter values.
- **Severity:** slang's severity (WARNING), Established. A finding meeting V1 to V6 is INFO, Established: the message keeps slang's text and adds the proof, recorded as evidence `value_preserved`. Every other shape stays WARNING, including one where the proof is missing. Three shapes are INFO by type policy, not by proof, because synthesis builds the same bits: a packed-array-conv between two packed types of the same total width whose destination elements are plain bits or packed structs of plain bits (no enum, no union) and that does not put 4-state data into a 2-state type; a case-type between an enum and a plain vector of the same width; and a bitwise-op-mismatch of two integral operands of one width, whatever their types, signedness or 2/4-state kinds (an enum xor a vector), since a bitwise operation computes on bit patterns. A bitwise mismatch of different widths is LNT-004. An enum destination, a struct with an enum field, a width change, 4-state into 2-state and two different enums stay WARNING. A finding inside a definition no instance of the design uses is INFO, evidence `definition_not_instantiated`: slang elaborates it with unresolved parameters, nothing in it is evaluated, and LNT-011 already says the module is not linted.
- **Unknown:** none: decided by slang and by the AST shape above.
- **Limits:** a negative constant overriding an unsigned parameter of a child instance (`#(.W(-1))` into `parameter int unsigned W`) converts silently and is not reported; the value proofs walk the override expressions of a child (`.Width(NumShares * Width)`) but this sign change is no comparison or assignment they examine. Pre-existing.

### LNT-006
- **Trigger:** (a) constant selects: slang options index-oob, range-oob, range-width-oob, range-select-reversed; slang codes IndexValueInvalid, RangeWidthOverflow, ScopeIndexOutOfRange. (b) opt-in (`LNT-006.dynamic_index=true`): a non-constant element select of a fixed-range array or vector whose index can take a value outside the range: the values of a `for` loop variable that starts at a constant and steps by a positive constant towards a constant bound, with no other write to it in the body; otherwise every value of the index's type. (c) always on: an element select indexed by exactly such a loop variable, or by an exact affine function of one (`i+1`, `2*i`, `i-1`, `i<<1`: `+ - *` and `<<` by constants, every node fitting its own type), in code the design can run (a branch that a constant condition excludes, such as `if (N > 8)` with N = 4, is not, nor is the unselected arm of a constant `?:` or the right operand of a `&&` after a constant false), where the loop body contains no `break`, `continue`, `return` or `disable` (a `disable` of a block that holds the select, before it, skips the select as well), the select is not under a condition, a `case`, a `?:`, a short-circuit operand or an inner loop of that body, and some value of the index's range lies outside the selected range. A condition that compares the loop variable (or an affine function of it) with a constant narrows the variable's range inside the branch it decides, so `if (i < 7) a[i+1]` is silent; a guard that lets the bad value through (`i < 7 || en`) is judged by (b), where its finding is the WARNING for a select that may run. Every iteration then runs the select, so the overrun is certain. (b) is on by default for an index or an indexed part-select base (`+:` / `-:`) whose range comes from a free input (an obligation); `dynamic_index=true` adds those fixed by constants and loop counters (WARNING), `=false` turns (b) off. A condition that compares the variable with a constant narrows it inside the branch (ANALYSIS.md Value ranges). A constant out-of-range select is no elaboration failure: the run goes on.
- **Exempt:** (b) indexes whose possible values all lie inside the range; non-integral, wider than 62-bit and dynamically sized selections (no fixed range). (c) any weaker shape is left to (b). A write to the variable in the body, including through an output, inout or ref argument of a call, removes the loop's range; an index inside an assignment target is a read. The statements after `if (c) break;` (or `continue`, `return`, `disable`) in one list run only when `c` is false (a `disable` leaves only a block, or the task, that encloses it: one that does not is not running and leaves nothing, so it narrows and kills nothing), so `c` narrows what they read like a branch condition; a select after an unconditional jump never runs and is not reported. A block-local variable written once keeps the range of that write only when nothing else writes it: a second write through a concatenation, streaming or assignment-pattern target, an output or ref argument, or an increment voids it.
- **Severity:** (a) slang's severity (WARNING or ERROR), Established. (b) depends on what decides the index. Constants and loop variables alone (range computed, see ANALYSIS.md Value ranges): WARNING, Heuristic when the range leaves the selected range (a loop's range bounds its values but does not show each occurs: a guard or `break` can skip one), nothing when it stays inside, and WARNING, Unresolved without an obligation (a gap) when the range cannot be computed. Any other index (an input, a signal, a call): WARNING, Unresolved, the obligation below, unless the range its operations allow lies inside. (c) ERROR, Established (a proven overrun, like slang's constant `index-oob`), naming the first value outside the range; it replaces (b) for that select. In a task or function nobody calls in this design it is WARNING, Unresolved: the code may be reused. A function whose every call lies in a branch a constant condition excludes, in a generate block that is not elaborated, in the unselected arm of a constant `?:`, or in the right operand of a `&&` after a constant false (a `||` after a constant true), counts as uncalled. A function that one specialisation of a module calls and another does not is reported once, as the error.
- **Unknown:** (b) whether the design keeps a free index in range is not analysed (an input contract, a clamp elsewhere); that is the Unresolved finding. A guarded select in a loop that overruns is decided only by (b).
- **Limits:** the opt-in dynamic mode (b) reads only the guard forms listed in ANALYSIS.md, other guard shapes keep the finding. Formal ranges (an `input` of a function) are collected from call sites that `visitHardware` reaches; a call site outside that visit does not contribute.
- **Obligation:** `index-input-contract`: the free-index finding (b), non-blocking by default; an index whose range is known is a defect or silent, never this obligation.

### LNT-008
- **Trigger:** a user-declared module-level net or variable (not a port) that is integral and not a struct, union or array, with at least one driver (or a write through a non-constant index), whose static driver bit ranges leave some bit of its selectable width undriven.
- **Exempt:** ports (LNT-024); aggregates (LNT-041); symbols with no driver at all (slang reports these as undriven-net, undriven-port or unassigned-variable, all mapped to LNT-008), except a variable or net of any type whose only writes are dead code (after an unconditional jump, under a constant-false condition, including an `&&` with a constant-false operand such as `we && EN` with `EN = 0`, or a condition, a loop entry condition, an event `iff`, a jump guard or the selector of a `case`, `casez`, `casex` or `case inside`, that an input port every instance ties to the same constant decides (`we` tied to `1'b0`, a two-bit `en` tied to `2'd0` against the label `2'd1`), in a loop that runs zero times; a write made by a subroutine is dead when no live call reaches the subroutine: every call, in any depth of calls, is in such code, or there is none): WARNING, Established, "never driven".
- **Severity:** WARNING, Established, for a static gap. An `inout` port that the module only reads acts as an input (the net it is wired to supplies the value, nothing in the module could drive it): slang's "undriven output port" for it is INFO, Established, with that reason; an output port nothing drives stays WARNING. A driver written inside a `translate_off` region (LNT-083) is not a driver for synthesis: a signal with no other driver is WARNING, Established, "never driven for synthesis".
- **Unknown:** WARNING, Unresolved ("cannot determine which bits ... are driven") when a driver is not fully static, or when a gap is left and a write uses a module-level index or a loop-indexed write is not proven to drive every bit it names (`v[i]` in a `for` loop whose every iteration runs the write, with the values of `i` known; see ANALYSIS.md). The slang driver of a write whose index is still not constant after unrolling (a `for` loop whose body writes its own variable, any `while`, `do`, `repeat` or `forever` loop, an index with a block-local offset, a write in a called subroutine) is never counted as coverage; only the loop proof places bits for it, and a `foreach` indexed by its own variables counts as slang reports it. A module-level index write that leaves no gap is not reported. A static write slang lists no driver for (after a `continue` that runs, in a loop it takes for never executing) is a possible driver: a gap it might fill is Unresolved, never claimed undriven. A `for` loop over a module-level procedure temporary (ANALYSIS.md) with a constant start, bound and step is proven like a block-local counter, also with a call in the body that does not write it. A signal wired only to an instance of an unknown module (slang: "never assigned") is WARNING, Unresolved: the module may drive it. A symbol some of whose writes are dead and some live is covered by the drivers that are not dead plus the bits of its live writes: the bits only dead writes name are "undriven bit range", WARNING, Established. A variable all of whose writes sit under a condition on an input some instance ties to a constant that the ties do not decide for every instance (the instances differ, the tie covers only part of the selector, the condition also reads a free signal or a run-time label; a write made by a subroutine sits under the condition of the calls that reach it) is WARNING, Unresolved: a tied-off instance never drives its copy.

### LNT-009
- **Trigger:** (a) slang options multiple-cont-assigns, multiple-always-assigns, mixed-var-assigns and slang codes MultipleUWireDrivers, MultipleUDNTDrivers; (b) a module-level net of kind wire, tri, tri0, tri1 or trireg with two continuous drivers (continuous assignments, the net's declaration assignment `wire w = a;` and gate or primitive output terminals, the parent's connection to an input port net, which an assignment inside the child then overlaps, and what instances drive through an `inout` port connection, mapped bit for bit through a net, a constant select or a concatenation, recursively, which slang does not count; the same module driving an interface net from two instances, each identical interface instance being its own net (its own assignments, in a generate block too, repeated for each), a write through an interface port attributed to the instance that makes it and the net or element it reaches, followed through that instance's own port connections (a port passed down through further children, interface array elements, a second identical wrapper), and a modport port defined by an expression followed through it; an attributed black box on an inout net may drive it; not instance outputs) that drive an overlapping bit range, reported at the later driver once per net; (c) a user-declared net or variable where an output-port driver (instance output connection) and another continuous driver drive some of the same bits, reported at the later source position, except tri, triand, trior, tri0, tri1, trireg, wand and wor nets and continuous drivers whose RHS contains a 'z literal; (d) a variable written on overlapping bits by two plain `always` procedures, reported at the later one; a write whose element or bit is chosen at run time (an index that reads module-level state other than a loop counter) overlaps another writer when that writer writes every bit or word of the variable (a whole write, or writes that together cover it), or when both write a packed vector and the bits their selects can reach (a selector of one narrow variable built from `+ - * / %`, shifts, concatenation, constant bit- and part-selects, a packed struct member, `$signed` and `$unsigned`, every value tried) share a bit, and does not when both reach known sets that share none; a write indexed by a module-level loop counter writes the bits or words its loop reaches (constant start, bound and step, none left early), like a block-local counter; the same module writing an interface or hierarchical variable from two instances is two writers; otherwise it cannot be shown to overlap. For (b)–(d) an `initial` procedure gives an initial value and is not a driver; slang's (a) still rejects an `initial` write to a variable an `always_ff` drives (IEEE 1800 9.2.2.4), which stays ERROR. - **Exempt:** (d) a variable declared inside a subroutine or block, and a module-level procedure temporary, decided from the code (ANALYSIS.md): every read in every procedure and subroutine follows a write of the whole variable in the same activation (a `for` initialiser, an assignment before the read), a procedure writes it, and nothing else names it, and no write is nonblocking (a flop drives it) (a read or write anywhere else, a port, a hierarchical reference or an event control, makes it state); a driver whose right-hand side is a constant that is all z; `pullup` and `pulldown` gates (weak, resolved by strength); a tri-state pair whose enables are provably exclusive (`en ? v : 'z` against `!en ? w : 'z`; `bufif1`/`notif1` against `bufif0`/`notif0` with the same enable signal); wand, wor, triand and trior nets. A driver with x bits or with only some z bits drives and is not exempt.
- **Severity:** (a) slang's severity; (b) ERROR, Established, only when every driver in the conflict is attributed exactly to its instance and net, and no driver can release the net (a proven conflict); WARNING, Unresolved, when a driver can (an operand or `?:` arm that is an all-z literal or a named constant, parameter, localparam, enum or package constant, whose value is all z; a bufif0/1, notif0/1, MOS or tran gate; for an input port net, a parent connection with such a z or an inout, an instance output, or a releasable net in it) and the enables are not proven exclusive, or when the drivers have different drive strengths (an open-drain pair, `highz0` or `highz1`, releases the net; a weak or pull keeper against a stronger driver: simulation resolves them by strength and synthesis may ignore strengths); equal strengths (weak against weak, supply against supply) are unordered and give the ERROR like two strong drivers; (c) WARNING, Established (an instance output may release the net); (d) ERROR, Established (two procedural drivers, as slang reports for always_ff) when constants decide the overlap; WARNING, Unresolved, when a run-time index decides it and the cases above do not (a memory with two write ports is a real design that needs a true dual-port RAM, and the message says so).
- **Unknown:** (b) with an all-z literal in a driver: "driver conflict cannot be excluded" (Unresolved, above). (c) WARNING, Unresolved, "driver overlap is not determinable", when a non-constant index writes the symbol or one of its drivers is not fully static. (b) a black box on an inout net: WARNING, Unresolved, "a black box may drive this net"; an inout connection whose bits cannot be mapped counts as every bit. (d) WARNING, Unresolved, "driver overlap is not determinable", when either overlapping writer uses a run-time index and neither case above decides it (an unpacked memory, a selector of another shape, a loop counter whose loop range is not constant). A write in an unrolled loop that an exit (`break`, `continue`, `return`, a `disable`, a call that leaves) certainly runs in some iteration or cannot judge is undecided too: WARNING, Unresolved, "one of them in a loop that may be left early"; an exit that only may run (it depends on design state) leaves every unrolled write in the hardware, so the overlap is judged by structure (ERROR). Where every exit of the loop can be judged (a `break` or `continue` whose conditions are evaluated per iteration, enclosing counters enumerated) and slang's drivers lie within the iterations that can run, they are exact: an overlap in a live iteration is an ERROR, the dead iterations take no part, and only an overlap there gives no finding; where they do not (the exit is decided through a local copy), the pair is Unresolved. A `continue` is never trusted to drop the later iterations: slang drops every iteration after it, so the loop also counts at every bit its index reaches, as an undecided writer, while the bits slang lists before it are certain. This applies to `always_comb`, `always_ff` and `always_latch` loops too, unless slang's own diagnostic already covers the pair. A driver whose attribution through identical instances cannot be confirmed (a copy slang made that is not accounted for, a write whose target cannot be followed, an interface counterpart not found) counts as a driver and gives WARNING, Unresolved, "driver attribution through identical instances is approximate", never an ERROR and never silence. A write slang's driver list drops (after a `continue` that runs, in a loop it takes for never executing), found from the syntax, joins as a writer: certain when nothing guards it (a write after a loop with a `continue`), else undecided (WARNING, Unresolved, "code slang's driver analysis drops"). An `alias` of nets: WARNING, Unresolved, "drivers of the aliased nets are not combined" (the conflict is not analysed).

### LNT-012
- **Trigger:** on the shared model (combinational edges only; register and async-control edges end a path): (a) a bit that depends on itself through combinational logic (self-dependency, recorded per procedure or assignment); (b) a strongly connected component of more than one node, through ports and hierarchy.

Other block locals are analysed like any variable. A `for` loop whose bounds and step are constants (at most 256 iterations, no `break`, `continue`, `return` or `disable`, no user call, no write to its variable) is unrolled in the model: each iteration is walked with its variable bound, so its indexed edges are exact bit for bit and a cycle through it is established, and an arm of a `?:` (or the right operand of `&&` / `||`) that a condition constant under the bound variable excludes makes no edge. A self-dependency beside a computed index (`x = mem[i] ^ x`) is decided when the self term is a plain operand of a bitwise chain of the target's own width: it reaches the target bit for bit whatever the index reads.
- **Unknown:** a black box (an unknown module, an attributed black box or a `--library` blackbox) may pass any input to any output without a register: a cycle that needs such a path is WARNING, Unresolved, located at the box. A library port declared synchronous to a clock, and a clock port, take no part; a cycle that goes in and out of a box without any logic is not reported, and one that stays when the box is removed keeps its own severity. signals wider than the per-bit limit are one node: a cycle through them is WARNING, Heuristic ("wide signals are tracked as one node"). A state or inout argument that a call reads is a read of the procedure's own value when `Flow` shows it written before the call. Components that differ only in the bit position of the same signals and procedures (a loop over a vector or array) are one finding, with the number and range of bit offsets in the message. Each cycle carries an ordered `cycle_step` witness of the shortest loop.

### LNT-025
- **Trigger:** within one procedure, an earlier conditional write v and a later conditional write w of the same variable, of the same write kind (blocking in combinational, latch and level procedures; nonblocking in clocked procedures), with both writes static (exact bit ranges), v's bit range inside w's range, both guard lists non-empty, neither write inside a loop body, no read of the variable that can see v (`!readBefore`), no timing control between them (`!observed`), neither guard list implying the other, and `!exclusive(v, w)`: when both conditions hold, w replaces v's bits.

### LNT-029
- **Trigger:** a direct scalar-enum transition case: its selector belongs to the nearest sequential state symbol's upstream value-dependency relation, and its case body assigns a symbol in that relation. (a) An enumerator absent from all known constant assignments and declaration initializers in that relation is a dead-state candidate. (b) A single-expression, non-empty arm that has no transition is a stuck-state candidate: it has no related assignment, or only holds (`nx = st`, `st <= st`), and no assignment elsewhere in its procedure can move it: a hold, a write in the block's own reset branch (an event-list reset or a KNOWN one, `if (!rst_n) st <= IDLE; else case (st)`: the reset is the one exit a stuck state keeps), and a write under a condition that requires the state to be a different value (`if (go && st == DONE) nx = DONE;`) do not count. A write in the other branch of an `if` that holds the case, or in a sibling `if` before it, that is not the reset (`else if (abort) st <= DONE; else case (st)`) moves the state out of the arm and suppresses (b). The transition graph (ANALYSIS.md, FSM transition graph) also reports (c) an enumerator no item lists that the default or the value held before the case keeps in place (WARNING, Established), and (d) states no transition reaches from the reset or initial states (INFO). The graph that answers LNT-071 reads each guard as a formula (ANALYSIS.md, FSM transition graph); an arm that assigns its own state constant is a hold for the arm check.
- **Exempt:** output-only enum decoders; sharing an enum type with a clocked register alone is insufficient. Downstream readers do not contribute assigned values to the state. Unknown values suppress (a); an outside-case assignment that can move the arm suppresses (b). A continuous assignment (`assign raw = st_e'(code)`) and an input port give a state values the inventory cannot list: they are unknown values. These are structural candidates, not liveness proofs.
- **Severity:** WARNING, Heuristic for candidates; WARNING, Unresolved, NOT_ATTEMPTED for an ambiguous or opaque recognized relation.
- **Unknown:** user calls in a known-state candidate procedure may have hidden state effects; unsupported value computations and equally near state roots require review. Same-enum direct aliases, conditional data arms and declaration constants are inventoried; casts across enum types are not assumed value-preserving. A case on an enum whose procedure writes that enum type, with a selector that is not one scalar state symbol (array element, dynamic or element-selected path, cast, call result) or that no clocked state of the type reaches (state held in another scope), is WARNING Unresolved, NOT_ATTEMPTED; a procedure that writes the type only as a member or element of a record (`core.cmd = INV`) and no variable feeding a clocked register of it builds a data value, not a state, and its case is no state machine. Next-state logic in a function that returns or outputs the state's enum type (the case sits in the function) and a state coded as an if / else-if chain of comparisons with two or more enumerators, with no case on it, are WARNING Unresolved, NOT_ATTEMPTED: their transitions are not read.
- **Not analysed:** every Unresolved finding of this rule, including a relation the inventory cannot attribute (state in an array or another scope), is a tool gap, not an obligation.

### LNT-033
- **Trigger:** a user-code `unique` or `unique0` case whose items can match a common value, or a `unique`/`unique0` if chain with two conditions that are both true (constants) or that are the same expression (same symbols, operators, selects and constants, no calls or side effects). - **Limitation:** overlap is judged on two-state selector values; Z wildcard matching by a released `unique casez` selector is outside scope because synthesized logic has no Z wildcard.
- **Exempt:** priority cases and priority if chains; non-overlapping items; values repeated inside one item.
- **Severity:** ERROR, Established.
- **Unknown:** WARNING, Unresolved, once per statement, "claim not statically checkable": an item or condition is not a constant (and the conditions are not provably the same), or the selector is wider than 64 bits; an `inside` item with no earlier item overlapping under both typings but one overlapping under only one (ERROR when any earlier item overlaps under both): WARNING, Unresolved, "whether the items overlap depends on how the set is typed".

### LNT-036
- **Trigger:** in user code, (a) a `*` whose evaluated width is less than the sum of its operand widths (a constant operand counts its significant bits): WARNING, Heuristic ("product truncated"); (b) a `+` or `-` that is an operand of a concatenation (not a replication) with two non-constant operands whose result width equals the wider operand's width: WARNING, Heuristic; (c) only with option LNT-036.report_modular=true: a non-compound `+` or `-` assigned to a target of exactly the operand width, both operands non-constant: INFO, Heuristic. (d) a direct binary `+` or `-` used as the count of any logical/arithmetic shift whose abstract operand range exceeds the count result's signed/unsigned representable range: WARNING, Heuristic. This does not prove the extrema are reachable together. (e) a `+` or `<<` of non-constant operands (a `<<` by a constant count; run-time shift counts are LNT-035's, except the own-operand compare `(a << s) < a`; a sum beneath a run-time left shift that is compared (`((a + b) << s) > c`) is still its own site), evaluated at its operands' own width (no wider context), whose value range exceeds that width, and whose result is the left operand of `>>`, `>>>` or `/`, or an operand of a comparison: the carry the next operator would use is already lost (WARNING, Heuristic; a signed `-` counts the same; silent when a wider operand or target widens the expression, or the value ranges (followed through a net with one continuous assignment) show no carry; silent also when an accumulator proof bounds an operand register, ANALYSIS.md, Accumulator bound). An unsigned `-` is modular on purpose (`(now - start) >= timeout`), but only the difference itself: a `+` or `<<` operand beneath it is its own site (`(a + b - c) < d`, `(c - (a + b)) >> 1`, `((a << 2) - c) < 9` are reported). A constant addend or subtrahend does not hide the sum beneath it: the value range of the whole chain decides (`(a + b + 8'd2) > 20` and `(a + b + 8'd1) >> 1` are reported, `127 + 127 + 1` in 8 bits is not). An unsigned sum compared with one of its own operands (`(a + b) < a`, also through a same-width cast `8'(a)`) is the overflow test and is not reported; for a signed sum, or a shift, it is not an overflow test and is reported. (f) a `+` or a left shift by a constant of non-constant operands whose whole value range lies beyond what its evaluated width holds (`{1'b1, a[6:0]} + {1'b1, b[6:0]}` in 8 bits is at least 256): WARNING, Heuristic, whatever consumes the result, since no input makes it fit; a range that only reaches past the width stays (e)'s, and a wider context or target keeps the value.
- **Exempt:** constant operands for (a)/(b); for (b) a sum that is the least significant operand with only constants above it, at least as wide as the sum (`{32'b0, a + b}`: a modular sum zero-extended into a wider word, not a carry slot; INFO "the carry of the sum is dropped by the concatenation; intended for a modular sum" instead of the WARNING; `{1'b0, a + b}` is reported); non-integral (real) arithmetic; compound assignments; for (a)/(b) an operation whose value range (ANALYSIS.md, Value ranges) fits the evaluated width (a loop variable or a narrow unsigned operand times a constant, a remainder times a constant), also inside an `if`/`else` branch or `?:` arm whose condition bounds a variable: the variable against a constant, or a net assigned that comparison (`assign done = q >= N`), through `!`, `&&` and `||`, unless the procedure writes the variable by a blocking assignment. Manual sign extension under `$signed` uses the original signed operand range, including repeated sign bits. Shift counts use direct binary addition/subtraction only; explicit widening casts are respected. An `input` formal of a function has the range of what every call passes (`rotr(v, 6)`: `32 - amt` is 26), unless the body writes it or some call cannot be read; a formal whose calls include a free signal has its type's range.
- **Severity:** WARNING, Heuristic, for (a), (b) and shift-count overflow; INFO, Heuristic, for (c) and for a sum zero-extended by a constant pad. Direct add/subtract shift counts beyond the supported range model are WARNING, Unresolved, NOT_ATTEMPTED.
- **Unknown:** a missing range proof keeps the arithmetic finding; unsupported shift-count ranges are Unresolved.

### LNT-037
- **Trigger:** (a) slang option divide-by-zero: a constant divisor of zero. (b) a non-constant integral divisor of `/` or `%` whose values include zero: a `for` loop variable's range (as for LNT-006), otherwise every value of its type. By default only a divisor that reads design state (a port, net or variable of a module or generate block, also through the body of a function it calls; a callee whose body cannot be read counts as design state) is examined; `LNT-037.dynamic_divisor=true` also examines divisors fixed by constants and loop counters, and a subroutine's formal (the callers' to constrain).

(b) a divisor decided by constants and loop variables alone: WARNING, Heuristic when its range includes zero, a gap (Unresolved, no obligation) when the range cannot be computed; any other divisor: WARNING, Unresolved, proof NOT_ATTEMPTED, the obligation below, unless the range its operations allow excludes zero.

### LNT-038
- **Trigger:** in user code, (a) a comparison (`==`, `!=`, `===`, `!==`, `<`, `<=`, `>`, `>=`) of a plain runtime reference (identifier or select with a pure index) with an integer constant of at most 62 bits (for an unsigned operand wider than 62 bits also a fill literal) and no X/Z bits, when the result is the same for every value the reference can take in its signed or unsigned domain; (b) a comparison of one plain runtime reference with itself, true for `==`, `===`, `<=`, `>=` and false otherwise; (c) `a && !a` (false) or `a || !a` (true) on one plain runtime reference; (d) a comparison of any other runtime integral operand (a concatenation with a constant zero top, a mask, a sum in a wide context) with a non-negative constant, when its value range (ANALYSIS.md, Value ranges) lies strictly inside its type's and every value in the range gives one answer: `{1'b0, sel} < 4'd8` with a 3-bit `sel`.
- **Exempt:** comparisons where both operands are constant (LNT-018 domain); operands that are calls, arithmetic or selects with a non-pure index (not analysed for (a); (d) reads their value range); an operand whose range is not narrower than its type, can be negative or reaches past 2^62, and a negative constant for (d); X/Z and real constants (silent here; LNT-040 covers X/Z comparisons). A negative constant no wider than an unsigned operand is compared by its bit pattern, which the operand can take. An unsigned operand wider than 62 bits against zero, a fill literal or a constant of at most 62 bits takes every value from zero to past 2^62, so only `< 0`, `>= 0` (and `> '1`, `<= '1`) are constant: those are reported (WARNING), every other test is not a tautology.
- **Severity:** WARNING, Established; INFO when the constant operand references a parameter or genvar.
- **Unknown:** WARNING, Unresolved ("comparison is outside the modelled domain") when the constant is wider than 62 bits (a fill literal of all ones excepted, against an unsigned operand), a signed operand is wider than 62 bits, or a negative constant wider than the unsigned operand is compared with it.

### LNT-039
- **Trigger:** in user code, an X or Z literal (unbased unsized, or sized with x or z bits) anywhere in the value of an assignment right-hand side, a continuous assignment, a variable or net initialiser, a return value, a `?:` arm (an operand such as `a & 1'bx` puts X into the value too), an input or inout port connection (a continuous assignment of the actual to the port), an input or inout terminal of a gate or user-defined primitive instance (driven like a continuous assignment; a gate or UDP reads a 'z input as x, so only a switch's data terminal can carry the tri-state INFO), or the default of an input port (the value an instance takes when it leaves the port unconnected; a top-level input port's default is checked too, as no instance connects it), an input or inout argument of a task or function call (the value the formal takes, wherever the call sits), or the default of such an argument when the call uses it. A named constant (parameter, localparam or enum value) with X or Z bits in any of those positions is reported the same way, whether it is named directly, hierarchically or through an interface port; an unpacked array or struct constant counts through all its elements and members. A select or member access of a named constant, through any chain of selects and member accesses, is judged by the bits it selects when its index or range is constant; a non-constant index, or one that calls a user subroutine, judges the object it selects from.
- **Exempt:** literals in comparisons and in the condition of a `?:` (both LNT-040); the connection of an output or ref port, an output terminal of a gate or user-defined primitive, and an output or ref argument of a call (each drives its actual and writes no value); an input port default that the instance overrides with a connection; a select or member access with a constant index whose selected bits hold no X or Z, and a select with a non-constant index of an object that holds no X or Z; the value expression of a parameter or localparam declaration and of a parameter override (an X there is reported where the parameter is used as a value, and a `?:` arm in it is not reported).
- **Severity:** WARNING, Established; INFO, Established, for an X-free 'z literal or named constant assigned to a net or a net port (tri-state). The tri-state INFO is for an integral value that reaches the net unchanged: the whole right-hand side, a `?:` arm, an operand of a concatenation or replication, or a constant select of a named constant, with no operator, call, index or value-changing conversion in between (`a & 1'bz` and `~HIZ` are X, so WARNING). A conversion changes the value when it changes the width or sends a 4-state value to a type with a 2-state bit (`bit'(1'bz)` is 0). The target must be a net in every bit it writes: a concatenation, select or struct member counts through its operands and root (`{w1, w2} = 2'bzz`), and a variable in it makes the target a non-net. An unpacked array constant of all 'z driving a net array stays WARNING, since the INFO is for an integral value. INFO for any of these inside a final block or assertion. A sized 'z narrower than its net is zero-extended, so it also drives 0 bits and is WARNING; an unbased unsized `'z` fills every bit. The INFO needs every bit that reaches the net to be z: a literal with 0 or 1 bits (`2'bz1`), or a narrowing that keeps one (`2'bz0` into one bit), drives those bits and is WARNING. A signed sized 'z sign-extends, which repeats z, so it stays INFO when a plain assignment or argument extends it or its `?:` is signed (`w = 4'sbz`), and is zero-extended when a `?:` arm extends in an unsigned conditional (`s ? 2'sbzz : 2'b00` is WARNING). A conditional or constant all-'z that reaches an `input` port of an instance, or a net with no other driver (no port, no instance inout, no gate on it), is WARNING, Established: nothing can drive it, so it floats. A net with several drivers, an inout or an output stays INFO.
- **Per bit and by function:** a net that only one assignment drives, counted per bit (`assign t[0] = 1'bz; assign t[1] = x;` leaves bit 0 with this one driver, also per generate iteration), is a floating net, and so is a call of a function that returns an all-z constant; a `tri0`, `tri1` or `trireg` net released to z is pulled or keeps its charge and stays INFO. Multi-driver nets and inout pads stay INFO. Independently of that count, a bit of a net (a wire or tri, not a port, no declaration assignment) that an instance input reads by a static select, and whose every driver is constant z (counted across part-selects, a whole-vector z under a driven part, member selects and the z bits of a concatenation) with no other driver, instance output, inout connection, switch, gate or pull on that bit, floats: WARNING, Established, at the assignment that drives it z. A driver or a drive whose bits are not static makes the net unjudged (INFO).
- **Unknown:** literal and named-constant detection, not variable tracking: an X that reaches a value through a variable, or through an actual that is a variable, is not followed (LNT-066 follows constant drivers). A connection to an interface port or a multiport is not followed. A select whose index does not fold to a constant, or calls a user subroutine (slang would run the call and fold one run of its static state), is judged by the object it selects from, and its message says the index may reach the X/Z bits. So a runtime index into an all-'z constant stays WARNING ("may reach"): the index is not decided, and the cautious reading is taken. Code in a generate branch this configuration does not elaborate, or in a definition the top never instantiates, is not hardware of the run and is not checked; LNT-051 and LNT-011 report those as INFO.

### LNT-041

### LNT-044
- **Trigger:** a module-level variable read in a combinational or clocked procedure where the read sees the value from before the procedure on every path (`entryOnly`), and a later non-compound write of the same variable exists in the procedure that covers the bits read (the whole variable, or the exact bits of a static select, an unrolled loop's included). ### LNT-082
- **Trigger:** architecture advice for a module-level unpacked array read by continuous assignment or unclocked procedure (not initial/final); collision uncertainty for an inventoried read, including a read inside a called subroutine body, when the array has a driver or a non-constant indexed write, including writes in another process and writes inside called subroutines. WARNING, Unresolved, NOT_ATTEMPTED, at a write and at a read, once per array and pair of clock sets; the read the collision obligation above already reports is not reported twice. A read outside a clocked process is not a cross-clock read here. No synchroniser or handshake is recognised: only the same or a proven related clock is quiet.
- **Obligation:** `memory-read-during-write`: collision uncertainty for an inventoried read; an unattributed memory in a struct or an unattributable called read is a gap. `cross-clock-array-read`: the phase between two unrelated clocks decides what the read sees.

### LNT-062
- **Trigger:** a nonblocking assignment whose target is a module-level variable (or a select of one; members resolve to their containing object; every operand of a concatenation target is a target) inside a combinational procedure: `always_comb`, `always @*`, or `always @(a or b ...)` without edges.
- **Exempt:** block-local temporaries; edge-triggered, latch and initial/final procedures; blocking assignments.
- **Severity:** WARNING, Established.
- **Unknown:** visible called writes use their own assignment kind and the caller context. Unexaminable bodies or unattributable targets are WARNING, Unresolved, with the reason. A common bit that lies only in an approximation (a select inside the word not placed), or a conflict through a write in a `case` arm that a constant selector leaves undecided, is WARNING, Unresolved.
- **Scope:** the selected elaborated configuration; uninstantiated definitions and generate alternatives are disclosed separately.

### LNT-063
- **Trigger:** a module-level variable (or a select of one; members resolve to their containing object; every operand of a concatenation target is a target) that is the target of at least one blocking write (including increment/decrement) and at least one nonblocking assignment in user code, in any procedure kind (including initial and final); reported once per variable at its first assignment.
- **Exempt:** block-local temporaries; continuous assignments and nets (not procedural targets in this check).
- **Severity:** WARNING, Established.
- **Unknown:** visible called writes use their own assignment kind and the caller context. Unexaminable bodies or unattributable targets are WARNING, Unresolved, with the reason. A common bit that lies only in an approximation (a select inside the word not placed), or a conflict through a write in a `case` arm that a constant selector leaves undecided, is WARNING, Unresolved.
- **Scope:** the selected elaborated configuration; uninstantiated definitions and generate alternatives are disclosed separately.

### LNT-064
- **Trigger:** an item of a `casez`, `casex` or `case inside` statement in user code whose constant value has every bit a wildcard, so that it matches every value and shadows the later items (wildcard bits: casez, Z or `?` only; casex and `case inside`, X and Z); the same for a `casez`/`casex ... matches` constant pattern, and for an unguarded pattern that matches every value (`.*`, `.name`, a structure pattern of such patterns, a tagged pattern of a one-member union) when an item or the default follows it.
- **Exempt:** items that are not constants (skipped silently); items with at least one non-wildcard bit (an X bit of a casez item is LNT-040's); plain `case` statements and plain `case ... matches` constants; guarded (`&&&`) items; a matching pattern that is the last item.
- **Severity:** WARNING, Established, when a later item follows the catch-all. INFO, Established, when only the `default` item (or nothing) follows it: it makes `default` unreachable and shadows no other item.
- **Unknown:** WARNING, Unresolved, once per `matches` statement, when a pattern cannot be decided (an invalid pattern or a constant that does not evaluate).

### LNT-065
- **Trigger:** slang options case-default, case-incomplete, case-none, case-not-wildcard, case-wildcard-2state, case-too-complex; slang codes MultipleDefaultCases, CaseStatementEmpty.
- **Severity:** slang's severity, Established: WARNING, except ERROR for several default items and an empty case. A slang case-default on a case whose items match every two-state value of the selector (plain case, casez or casex wildcards) is INFO. A diagnostic location shared by several specialisations of one module is INFO only when every specialisation's items match every value.
- **Unknown:** none: decided by slang.

### LNT-066
- **Trigger:** a node with an X or Z constant driver (a 'z driver of a net is its normal release and is not a source), or an X or Z reset value of a register, from which dependency edges that are not async-control reach an assignment condition: procedural guards (including case selectors), write indices, or conditional-operator selects in continuous or procedural assignments. One finding per condition site names all reaching sources, including constant-driver and reset origins. Conditions in a called function or task bind formals to actuals and are reported at the call, naming the callee.
- **Exempt:** 'z drivers of nets.
- **Severity:** WARNING, Heuristic.
- **Unknown:** flow-insensitive: another driver or an earlier override may mask the value (Heuristic). Called conditions bind formal reads to actual arguments and report at the call, naming it. An opaque callee, nested call or unexpanded callee-local dependency reached by a poisoned argument is WARNING, Unresolved.

### LNT-067
- **Trigger:** (a) the reset identification of LNT-020: a module-level variable, or a bit or element range of one, assigned outside the reset branch and not certainly reset by it (compared by range as LNT-020; a reset write counts only when it certainly runs, as in LNT-054); one finding per register, naming the bits the reset branch leaves out when it assigns the register in part; (b) from the model's per-bit reset values: for each register (flops with an asynchronous reset, grouped by name without the bit index) that (a) did not report, the bits that no asynchronous reset branch assigns, reported when some bit of the register is assigned by a reset branch or some of its flops have two or more asynchronous controls.
- **Exempt:** (a) as LNT-020 (single-edge blocks without a recognized synchronous reset, blocks with more than two edge controls other than the set-and-reset chain of LNT-020, variables assigned in both branches); (b) a register none of whose bits any reset branch assigns (left to (a)); a bit assigned a non-constant value in a reset branch counts as assigned (LNT-070).
- **Severity:** INFO: reset consistency is advisory; synthesis implements the specified hold behavior. Established, or Heuristic when the reset is chosen by name or a compound test. A use of undefined state in a condition remains WARNING under LNT-054.
- **Unknown:** (a) name-chosen resets and compound tests are reported as Heuristic (above); a branch tested by an UNDECIDED net (alone or beside a KNOWN test) and a finding that instances of the module do not all give are judged as LNT-020 judges them and reported only as WARNING, Unresolved. Unexaminable callees, unattributable targets, unclear reset branch attribution, and a reset write in a loop that may skip an iteration or run zero times are WARNING, Unresolved, with the reason. (b) the asynchronous bit values come from the model.
- **Scope:** the selected elaborated configuration; uninstantiated definitions and generate alternatives are disclosed separately.

### LNT-068
- **Trigger:** an `always_ff` block in user code that assigns a variable and has no asynchronous control and no KNOWN reset (the shared classifier of LNT-020: the reset inventory or an unambiguous reset name; `clr` and `clear` do not count) in its first if, inside an instance body where at least one other `always_ff` block has a reset.
- **Exempt:** instance bodies where no `always_ff` block resets.
- **Severity:** INFO, Heuristic.
- **Unknown:** a first test of a net whose reset identity is UNDECIDED (`rst_q`) is not called unreset: WARNING, Unresolved. Unless the branch it guards only loads data (`if (valid) q <= d;` stores no constant, so it is an enable and no reset question): then the block is called unreset like any other. Instances of the module that differ on whether a block has a reset are judged apart; a finding not given by every instance is WARNING, Unresolved, naming them.
- **Scope:** the selected elaborated configuration; uninstantiated definitions and generate alternatives are disclosed separately.

### LNT-069
- **Trigger:** a sequential block with at least two distinct edge controls in which (a) fewer than all-but-one of them are tested by the first if / else-if chain (controls are matched by full path, so `c[0]` and `c[1]` are two), or (b) all of them are tested, so no clock remains.
- **Exempt:** blocks with a single edge control; blocks in which exactly all but one control are tested.
- **Severity:** (a) WARNING, Heuristic; ERROR, Established when no edge control is referenced anywhere in the block body (a reference matches by full path, so `r[1]` is not the control `r[0]`; nothing to map as an asynchronous control, and the block also updates on the second edge). (b) WARNING, Established.
- **Unknown:** a user function call in the body could read a control, so (a) stays Heuristic then; a name-chosen reset not tested by the first if is reported under (a).

### LNT-070
- **Trigger:** a sequential block with an identified asynchronous reset whose reset branch assigns a right-hand side that `evalConst` does not evaluate to a constant, or assigns a target under an if or case in the reset branch whose condition is not a constant (a run-time value chooses the reset value; one finding per target). With one asynchronous control, the reset branch is the arm of the first if (or else-if chain) that a direct test of the reset with matching polarity selects. With three or more asynchronous controls, all but one or all tested by the first chain: the true-branch assignments of each if or else-if whose condition tests an asynchronous control.
- **Exempt:** with one control, reset branches not decided by a direct test (name-chosen reset or compound test) and blocks with a polarity mismatch (LNT-058); blocks where fewer than all but one control are tested (LNT-069). With several controls, polarity is not checked.
- **Severity:** WARNING, Established; WARNING, Unresolved, when the right-hand side contains a user function call.
- **Unknown:** user function call in the right-hand side: Unresolved (above).

### LNT-071
- **Trigger:** every direct scalar-enum transition case recognized by LNT-029; a possible relation obscured by calls, values or ambiguous state roots is reported Unresolved. Output-only enum decoders are exempt.
- **Severity:** WARNING, Heuristic, with proof state NOT_ATTEMPTED: reachability and liveness of every state are unproved. Reported only when the transition graph (ANALYSIS.md) cannot be read completely: Unresolved, NOT_ATTEMPTED. A graph that is read answers the question: reachable states without an exit are LNT-029. A reachable listed state whose only transitions lead back to itself (an own-value hold, an exit whose guard is never true) is a terminal state by design or a stuck one: the obligation stays (Unresolved, NOT_ATTEMPTED).
- **Unknown:** always NOT_ATTEMPTED: reachability of every state and absence of deadlock are not proven here. A guard that reads the state, the next-state variable or a net or variable assigned from them in a form not evaluated per state (anything but `==`, `!=`, an ordering or `inside` with constants, a bit select of the state, or a net that is one assignment of such an expression) leaves the graph undecided: the obligation stays.
- **Obligation:** `fsm-reachability-liveness` for the NOT_ATTEMPTED liveness finding.

### LNT-072
- **Trigger:** on the shared model, a reset net (the traced root of a register reset) that reaches the combinational logic of a clock domain root.
- **Exempt:** async-control edges (reset to register clear or set).
- **Severity:** WARNING, Established.
- **Unknown:** a reached opaque-cell boundary or truncated model dependency is WARNING, Unresolved, as for LNT-027.
- **Scope:** the selected elaborated configuration; uninstantiated definitions and generate alternatives are disclosed separately.

### LNT-073
- **Trigger:** a non-compound assignment in user code whose right-hand side evaluates to an integer constant (after implicit-conversion removal), including parameters, unary minus and constant expressions, whose target is narrower than that constant, and whose stored value changes under both the target's and the constant's signedness.
- **Exempt:** values that read back unchanged under either signedness (for example -1 into a 4-bit unsigned target keeps its all-ones pattern); compound assignments; constants with x or z bits.
- **Severity:** WARNING, Established.
- **Unknown:** none.

### LNT-074
- **Trigger:** a comparison (`==`, `!=`, `===`, `!==`, `==?`, `!=?`, `<`, `<=`, `>`, `>=`) in user code with an unsized integer literal (also under unary minus) on one side and an operand wider than 32 bits on the other.
- **Exempt:** sized literals; fill literals.
- **Severity:** INFO, Heuristic; the message gives the literal's actual width before extension.
- **Unknown:** none.

### LNT-075
- **Trigger:** a module, interface or program, library units (-v/-y) included, whose default net type in effect, as slang's preprocessor recorded it when the declaration was parsed, is not `none`. An `include`d directive counts, and so does an earlier file under `--single-unit`; `resetall` restores `wire`. slang has no command-line default-net-type option, and without `--single-unit` each file starts at `wire`.
- **Exempt:** declarations with `none` in effect.
- **Severity:** INFO, Established.
- **Unknown:** none. Use of implicit nets inside the design is LNT-007.

### LNT-076
- **Trigger:** a plain `always` procedure in user source.
- **Exempt:** specialized procedures.
- **Severity:** INFO, Established.
- **Unknown:** library units are not evaluated; choosing an appropriate replacement requires review.

### LNT-083
- **Trigger:** a comment that names a synthesis tool (`synopsys`, `synthesis`, `pragma`, `cadence`, `ambit`, `rtl_synthesis`) and a directive that directly follows the tool word, read from the source text (`//` and `/* */`; slang ignores them), in user sources; prose that merely mentions both (`// synthesis on an FPGA ...`, `// Synopsys DC needs no translate_off`) is no pragma. (a) `full_case` or `parallel_case` between a `case` header and its first item, or as an attribute on the case (`(* full_case *)`, `(* synthesis, parallel_case *)`): the tool builds different logic from the simulator (it assumes the missing values cannot occur and the items do not overlap). (b) a `translate_off` / `synthesis_off` ... `translate_on` / `synthesis_on` region (per file) that holds simulation-only code and also anything synthesis would build: a continuous assignment, an `always` block, an `initial` block that assigns design state, the declaration of a design signal, an instance with an output, a statement assigning design state inside a procedure, a case item, or the part of an expression the region boundary cuts (the region may start or end inside a procedure, a case, an assignment or an instance): simulation runs it, synthesis does not build it. Whatever such a region drives has no driver in synthesis: LNT-008 and LNT-024 count a driver inside a region as absent and report the signal as never driven for synthesis. (c) an unbalanced pragma: a `translate_on` with no `translate_off`, a second `translate_off` inside a region, or a region the file never closes.
- **Exempt:** regions whose statements are proven simulation-only: a system task call (`$display`, `$finish`), an assertion, an `initial` block that assigns no design state, a `final` block. Comment text that a preprocessor condition excludes is still read as a pragma; code the preprocessor excludes is not in the design and is not counted. A region is a simulation checker (INFO) only when every state it writes is declared inside it; increments, compound assignments, `force`/`release`, output and inout arguments, hierarchical targets, output ports and the writes of a called task or function (transitively) count as writes, as do a `ref` argument that is not `const ref` and a streaming target (`{<<{r}} = d`); a callee that cannot be read, or a target that names no symbol, keeps the WARNING.
- **Severity:** WARNING, Established. (a) is never escalated: whether the selector can take an uncovered value or two items can match at run time is not provable from the code; the message states the uncovered values or overlapping items when every item is a constant of a plain `case`. INFO when the pragma changes nothing (a complete, non-overlapping plain case), and for a closed translate_off region that holds only a simulation checker (its declarations are used only inside, it writes nothing outside); findings of other rules inside such a region are INFO.
- **Unknown:** a `case` whose items are not constants or whose selector is wider than 16 bits: the finding stays and says the effect is not decided. A region that holds only a call of a user subroutine, an instance without outputs, or a declaration of another kind (function, parameter, type, generate block) is WARNING, Unresolved: it is not classified as simulation-only. A pragma spelled any other way is not read.

### LNT-084
- **Trigger:** within one module, a net that is an asynchronous reset in the event list of one clocked block (identified as for LNT-020, a plain whole signal) and a KNOWN reset tested as a synchronous reset in another clocked block that has no asynchronous control in its event list (`if (!rst_n) q <= 0;` under `@(posedge clk)`).
- **Exempt:** nets that are only one of the two; the same net through different ports or after an inversion (not followed).
- **Severity:** WARNING, Established: the registers reset differently from one net, and the synchronous ones need the clock to run during reset.
- **Unknown:** a test whose reset identity is undecided is not taken as a reset (LNT-020 reports it). A reset used through a ternary or a mask (`q <= rst ? 0 : d`, `d & {W{~rst}}`) in a synchronous block is not read as a synchronous use.

### LNT-085
- **Trigger:** within one module, one clock signal on the rising edge of a clocked block and on the falling edge of another whose registers are different (one register on both edges is LNT-022).
- **Severity:** INFO, Established: synthesis builds what the code says; timing, duty cycle and scan insertion must cover both edges.
- **Unknown:** a clock that is not a plain signal is not compared.

### LNT-086
- **Trigger:** a module, interface or program instantiation in user source that connects a port by position (`sub u0 (clk, q)`), a parameter override by position (`sub #(8, 3) u0`), or a `defparam`. A user-defined primitive instance is not one.
- **Severity:** INFO, Established: synthesis builds what the code says; the style is fragile when a port or parameter is added. A width mismatch of a positional connection is LNT-004's finding, whichever way the port is named.
- **Unknown:** none.
