# RDC - Reset-domain crossings, asynchronous reset behavior and coordination

Titles must match `catalog.json` (a unit test checks this). Specification bullets are the contract each rule is tested against
(`tests/fixtures/<RULE-ID>/`). Reset recognition is structural; physical properties (recovery/removal, pulse width, glitches) and power intent
are explicit obligations/unknown markers, never "safe". Reset roots are traced through recognised reset synchronisers to their assertion source.

| ID | Required check |
|---|---|
| `RDC-001` | Reset-source inventory and registers without an identified reset root |
| `RDC-002` | Reset input with no constraint (unknown reset source) |
| `RDC-003` | Asynchronous reset deassertion not synchronized to receiving clock |
| `RDC-004` | Data crosses between different reset domains on the same clock |
| `RDC-005` | Data crosses between independently reset domains on different clocks |
| `RDC-006` | Reset synchronizer has too few stages or logic between stages |
| `RDC-007` | Reset generated by a register or logic in another clock/reset domain |
| `RDC-008` | Reset net combined from two or more reset sources |
| `RDC-009` | Reset gating/muxing that may glitch |
| `RDC-010` | Unreset register feeding a reset register of the same module instance |
| `RDC-011` | Several independent asynchronous reset sources: sequencing not modelled |
| `RDC-012` | Power intent not supplied: retention and isolation resets are not evaluated |
| `RDC-013` | Recovery, removal and minimum pulse width obligation for every asynchronous reset |
| `RDC-014` | Asynchronous reset driven by a data register that is not a reset synchroniser |
| `RDC-016` | Reset synchronizer stage fanout to logic |
| `RDC-017` | Reset mux/gate select from different reset domain |
| `RDC-019` | Asynchronous reset signal also used as functional data |
| `RDC-020` | Partial reset of packed state and dependent control |
| `RDC-023` | FIFO and handshake reset release sequencing |
| `RDC-024` | Reset request/acknowledge sequencing across domains |
| `RDC-025` | Primary output that depends on a register without reset |
| `RDC-026` | Several asynchronous controls on one register (set and reset, power-on and functional) |
| `RDC-027` | Reset-domain false-path exception does not imply safety |
| `RDC-028` | One reset used with both polarities, or a reset that is the inverted copy of its source |
| `RDC-029` | Retention or isolation reset boundaries when power intent provided |
| `RDC-030` | Reset synchroniser stages without consistent synchronisation attributes |

## Specification

### RDC-001
- **Trigger:** each asynchronous reset root R (the traced root node of a register's async reset event, any clock domain), polarity from the event edge (negedge = active-low; the last register bit seen for R is used), source kind TopPort, Synchroniser (final stage of a recognised reset synchroniser meeting `RDC-006.min_stages` whose receivers match its clock domain and edge and whose raw assertion sources all trace through exact/inverted copies and synchronisers to top-level ports), InvertedTopPortSyncInput (an inverted copy of a top-level port whose every asynchronous-reset user is a stage of such a recognised reset synchroniser), ReleaseFlop (the output of a register, through exact copies, forced asynchronously to its asserted level by a TopPort, Synchroniser or InvertedTopPortSyncInput source, whose D is the released constant and whose every asynchronous-reset user is a stage of a reset synchroniser recognised by chain shape, in any clock domain; the output has no other use), TiedInactive (constant-driven reset tied to its inactive level — literal, constant wire, parameter/localparam, or constant-tied port), TiedActive (constant-driven reset tied to its active level, holding its registers permanently in reset when the body forces a constant on that level, or reporting that the tie level does not match the tested level when the forced value is undecided), Logic, BlackBox (distinguishing a top-level input also connected to an unmodelled black box whose port direction is unknown from an internal black-box output), Undriven or Cycle; plus each synchronous reset candidate signal (leading top-level `if (s)` whose branch only assigns constants, or a trailing else-free `if (s)` suffix of constant nonblocking overrides in a clocked block).
- **Severity:** INFO (Informational) per R; WARNING (Established) per TiedActive R whose body forces a constant, or WARNING (Unresolved) when the tie level does not match the tested level; WARNING (Unresolved) per R that is not TopPort, Synchroniser, InvertedTopPortSyncInput, ReleaseFlop, TiedInactive or TiedActive; INFO (Heuristic) per synchronous candidate.
- **Unknown:** the Unresolved WARNING marks scope reset-extraction INCOMPLETE (TiedInactive and InvertedTopPortSyncInput are INFO with no WARNING and do not mark INCOMPLETE); the synchronous candidate is a heuristic on the condition shape: candidates are recognised by shape only (a tied-inactive candidate still exempts; case-form and else-arm synchronous resets are not candidates; limit: a conjunctive guard such as `if (rst && e)` is accepted as a synchronous reset candidate on shape alone, even though assertion requires every conjunct to hold). When a procedure's clock is ambiguous (e.g. a clock copy beside extra edge events) and a top-level condition tests an edge, every edge stays an asynchronous control (known force for tested controls, `?` for untested ones). Limits: a reset of a dual-edge event listed through exact copies reports one receiver with an unknown forced value, and redundant dual-edge spellings are unsupported; a packed-bit display names the register symbol, not the bit.

### RDC-002
- **Trigger:** (a) a top-level input bit R that is an asynchronous reset root (or a top-level input leaf feeding a combinational/gated asynchronous reset root) and has no applied, unrejected `set_input_delay`; one per R. Timing exceptions (`set_false_path`, `set_max_delay`, etc.) alone supply no reset contract and do not exempt R. (b) a top-level input bit with no applied, unrejected `set_input_delay` that contributes to a modeled synchronous-reset guard and is not an asynchronous reset root. Follow each guard through exact aliases, inversion, AND and OR for up to 64 nodes, stopping at register outputs. Report one finding per input, at the first register it resets.
- **Exempt:** an input covered by an applied `set_input_delay` whose port selectors resolve to supported top-level inputs, whose named clock is declared, and which has no rejected effective mode; under (a), a top-level reset input bit whose every asynchronous-reset use is a stage of a recognised reset synchroniser (reached directly or through exact/inverted copies only, never through combinational/gated reset logic) and which has no functional use (no synchronous-reset, data, or enable out-edge; same functional-use predicate as RDC-019; a clock use of the input is not counted as a functional use here — CST-011 reports an unconstrained clock); or a top-level reset input bit with no functional use whose every asynchronous-reset user is a stage of a reset synchroniser recognised by chain shape (whatever its consumer), a release flop, or release-safe in its domain (see RDC-003).
- **Severity:** WARNING, Unresolved.
- **Unknown:** the WARNING marks scope reset-extraction INCOMPLETE (the timing relation of R to the domains it resets is unknown).

### RDC-003
- **Trigger:** (a) each (asynchronous reset root R, clock domain D) with register bits in D reset by R (preserving packed-bit indices such as `top.rst[0]`), where R is a top-level port, a black box, undriven or cycle output, combinational logic with no register behind it, the output of a register with unidentified clock, or the output of a register clocked in D that is not a recognised reset synchroniser (a chain of nonblocking registers with established assertion/release assignments and no statement-level timing control or non-delay intra-assignment timing control — plain synthesis-ignored NBA delay controls `<= #d` are accepted for structural recognition, whereas event or repeat-event controls such as `<= @(posedge c)` or `<= repeat(n) @(...)` reject it: all stages asynchronously take the binary asserted level required by downstream reset polarity, share the same raw reset sources and polarities and clock edge, match the receiving registers' clock edge in D, the first stage takes the opposite binary released constant — directly, through a continuous assignment, or through an unconditional zero-delay `always_comb` copy/constant — each later stage takes exactly its predecessor, depth >= RDC-006.min_stages, default 2). Registers clocked in another domain are RDC-007; shallower recognised chains are RDC-006. (b) each register symbol with an asynchronous reset and no identified clock, one per name.
- **Exempt:** the stage registers of a recognised synchroniser fed by a top-level reset (directly or through exact/inverted copies, including constant XOR/XNOR polarity adapters, and recognised by chain shape regardless of downstream consumer when depth >= RDC-006.min_stages and non-final stages have no other fan-out); under (a), register bits with unidentified clock are skipped (CST-004 reports their paths; (b) reports them).
- **Severity:** INFO (Informational, proof NOT_ATTEMPTED) for a recognised synchroniser in (a) whose clock edge matches all receiving registers in D, or for a top-level reset port in (a) with an applied, unrejected `set_input_delay` whose effective contracts all declare a clock `Same` as D and which is not covered by a `set_false_path` or `set_multicycle_path` with `-from` or `-through` (trust model: release timed by the declared input delay; this input-delay INFO accepts opposite-edge receiving registers and `-clock_fall`, since STA times the half-cycle path); INFO (Informational, proof NOT_ATTEMPTED) for a top-level port R in (a) whose register bits in D are all release-safe (trust model: the release is ambiguous at no more than one edge of D); WARNING (Unresolved) for every other case of (a) (including a synchroniser with opposite-edge receiving registers, an input delay on another clock, or a port covered by a `-from` or `-through` `set_false_path` / `set_multicycle_path`) and for (b).
- **Release-safe:** for a top-level port R (directly or through exact or inverted copies, never a logic-combined root) and a clock domain D, a register bit reset by R in D is release-safe when (a) it is a stage of a reset synchroniser recognised by chain shape, whatever its consumer; (b) its D, evaluated in 0/1/X with the bits reset by R in D (same edge, one polarity, no other asynchronous control) at their reset values, every other register and every input X, and R released, equals its reset value, and it drives no asynchronous pin; or (c) it is a release flop (RDC-001). Bits failing (b) form a set U; the group is still safe when U is masked at the next edge: every register's D that reads U, U's own included, evaluates independently of U (a known result through a controlling constant is independent), U reaches no top-level output, clock pin, black box or asynchronous pin (except the asynchronous pins of recognised reset-synchroniser stages), and U reaches another clock domain only at the first stage of a recognised CDC data synchroniser. At the masking edge each register reads its value after the first edge: its reset value, or X when its D can differ from its reset value (stages and release flops included), and every net downstream of U reads X. A consumer whose clock event has an `iff` qualifier, which has timing inside its body, or which has several sequential drivers is not safe. Anything the evaluation cannot read (a call, a loop, an unsupported operator, a case with wildcards) is not safe.
- **Unknown:** every WARNING marks scope reset-extraction INCOMPLETE; the INFO records the trust model and never claims recovery/removal safety.

### RDC-004
- **Trigger:** a register bit d and a register bit s in d's fan-in cone (walk through Comb and Seq edges, stopping at registers), both in the same clock domain, where s has non-tied asynchronous reset sources rs as `(leaf, effective assertion polarity)` pairs (traced through recognised synchronisers, exact/inverted copies, and 1-bit constant XOR/XNOR polarity adapters `x ^ 1'b1` / `x ~^ 1'b0` as inversions and `x ^ 1'b0` / `x ~^ 1'b1` as exact copies; a constant-tied reset is omitted so a tied-inactive destination has empty rd, and an inverted copy with opposite effective polarity is a distinct pair) and rs is not a subset of the `(leaf, effective assertion polarity)` pairs rd of d (rd may be empty); one per destination symbol and pair of reset sets (preserving packed reset bit indices and generate-loop indices), listing each source symbol as evidence. A waiver scoped by `signal` must name the destination or cover every source.
- **Exempt:** rs a subset of rd (d is reset by every source and effective polarity that resets s); destinations held permanently in reset by a tied-active asynchronous reset that forces a binary constant (`RDC-001` reports the active tie); bits with unidentified clock (CST-004).
- **Reset propagation:** INFO, Heuristic (trust model) instead of the WARNING when s is the final stage of a recognised reset synchroniser (at least `RDC-006.min_stages` stages), every use of d is an asynchronous reset pin, an exact or inverted copy of one, or an exported reset output (a name with no reset word does not count; a name with a polarity must agree), and d's next value, evaluated with s at its forced (asserted) value and every other operand free, equals d's reset value, which every pin use asserts at. The generated reset is assumed to be used only as a reset. An unevaluable procedure, an enable or hold path, or an inverted use of s that releases d keeps the WARNING.
- **Severity:** WARNING, Heuristic; proof NOT_ATTEMPTED. Applicable `reset_contracts` clauses are cited as evidence and never change the severity.
- **Unknown:** RDC-004 does not walk through an unmodelled black box (`blackboxes` INCOMPLETE; `CDC-023` names the destination); a logic-combined destination reset is treated as its own reset source; a polarity mix on one reset net is reported by both `RDC-004` (same-clock crossing between opposite effective polarities of the same leaf) and `RDC-028`(a); destination tolerance to reset-induced value changes is not analysed, and the data crossing itself is a CDC question. Limit: a wide constant XOR/XNOR truncated to 1 bit (e.g. `wire rst_c = rst ^ 2'b10`) is not folded as a 1-bit constant polarity adapter.

### RDC-005
- **Trigger:** as RDC-004 for s and d in different clock domains whose ClockRelations relation is not Same (Async, Exclusive or Unknown).
- **Exempt:** rs a subset of rd; relation Same; destinations held permanently in reset by a tied-active asynchronous reset that forces a binary constant; bits with unidentified clock (CST-004); a destination register bit d that is the first stage of a recognised CDC data synchroniser (at least `CDC-005.min_stages` same-clock, same-edge, same-reset nonblocking flops with no inter-stage logic and no early-stage fan-out) when either (i) every consuming register reached from the synchroniser's last stage through combinational logic (with at least one consuming register and no direct primary-output or black-box escape) is itself reset whenever each missing source reset in rs asserts — either asynchronously by that source reset root directly, via a recognised reset synchroniser or synchronised register chain of it, or via a synchronous/OR-combined reset guard tracing to that source reset root or a synchronised register chain of it with matching polarity — or (ii) d samples directly (or inverted) as its sole data input a reset-propagation flag register s whose Q depends only on its single recognised asynchronous reset source (`TopPort`, `Synchroniser`, or `InvertedTopPortSyncInput`, not a data register; a combinational reset such as a scan mux is accepted only when every leaf of its fan-in is a top input or a recognised source, and is rejected when any leaf is another register, a black box or undriven; a top-input leaf is accepted only when it is a KNOWN reset input or is the select of a mux whose data legs are all top inputs or recognised reset sources (a constant leg or a missing else makes the input gate the reset, so it is a data leaf); a data input elsewhere, a latch or a combinational loop in the fan-in rejects it. Limit: a data input used as a scan-mux select between reset sources is trusted as a test-mode select; asynchronously forced to binary `v`, released D the opposite binary constant `!v`, with no non-constant sequential inputs).
- **Severity:** WARNING, Heuristic (Exclusive gives WARNING here, not INFO); proof NOT_ATTEMPTED. Applicable `reset_contracts` clauses are cited as evidence and never change the severity.
- **Meaning:** a reset-compatibility obligation, not proven destination corruption. Source assertion may change the transmitted value while the destination remains active. A data synchroniser resolves metastability, not the functional reset-domain crossing, so it is exempt only when every consuming register of the synchroniser is also reset on source reset assertion or when the sampled source is a constant-D reset-propagation flag; otherwise RDC-005 stays visible at WARNING. Shared assertion sources are structurally covered; otherwise tolerance, masking and reset sequencing need protocol evidence.
- **Unknown:** destination tolerance is not proved; the obligation stays visible at WARNING with proof NOT_ATTEMPTED whenever consumers are not structurally shown to reset on source reset assertion (including synchronisers whose output leaves the top module or enters a black box). The data crossing itself is a separate CDC question.

### RDC-006
- **Trigger:** a reset root R driven by a register chain in the users' clock domain that is a recognised reset synchroniser (see RDC-003) with depth < RDC-006.min_stages (floor 2, default 2); or a same-domain register chain (whose D cone contains a same-domain predecessor stage) that is not recognised because a stage's D has logic or several sources.
- **Severity:** WARNING, Established for too few stages; WARNING, Heuristic for logic or several sources on a stage.
- **Unknown:** an unrecognised chain always also emits RDC-003 WARNING (Unresolved) and marks reset-extraction INCOMPLETE.

### RDC-007
- **Trigger:** a reset R generated by a register g in clock domain Dg, directly or by combinational logic with g among its register leaves, and used by register bits in domain Du where relation(Dg, Du) is not Same; for the logic form, one finding per leaf register, selecting the worst-severity differing user domain (Async > Unknown > Exclusive). The logic walk stops at clock-domain nets (non-flop domain roots, clock signals, and their exact non-flop copies) so reading a clock net itself (e.g. `!clk_d & rst_n`) does not walk back through the clock tree to an upstream divider, clock-gate enable, or clock-mux leg register; direct reads of those registers in reset logic are still reported. The walk passes through intermediate reset roots (a reset built from another logic-built reset) and stops only at top inputs. One finding per (leaf register, receiving domain): a leaf that a root reaches only through nearer roots that already report that domain for the leaf (transitively along the root chain) is reported at the nearest such root; a leaf also reached by a direct path that skips every intermediate root is still reported at the outer root.
- **Exempt:** relation Same (no finding); receiving register bits in Du that are: (a) stages of a recognised reset synchroniser in Du (depth >= `RDC-006.min_stages`, recognised by shape regardless of downstream consumer — e.g. scan mux or valid flag — provided non-final stages have no other fan-out, and seeing through unconditional zero-delay `always_comb` copies/constants); (b) stages of a clean same-domain, same-edge nonblocking register chain of depth >= `RDC-006.min_stages` with no inter-stage logic and no early-stage fan-out where every stage is asynchronously reset by R with the same polarity and binary reset value (even when stage 1's D is data); or (c) a clean nonblocking receiving bit whose released D is a binary constant and whose every fan-out (through exact combinational copies) is the sole data input to the first stage of a recognised CDC data synchroniser in the same clock domain (with no primary-output, black-box, clock-root, async-control, or combinational-logic escape).
- **Severity:** ERROR, Established for Async; INFO, Established for Exclusive; WARNING, Unresolved for Unknown.
- **Unknown:** an Unknown relation is WARNING Unresolved and marks clock-relationships INCOMPLETE. A register reached only through the test-mode leg of a scan mux is still reported as ERROR; a crossing that exists only in test mode is a false alarm the user waives. A reset synchroniser whose output passes through a scan clock mux with a multi-bit (mubi) select is not recognised, because `set_case_analysis` on mubi bits is not applied (CST-009). Limit: the logic walk stops at any net that drives a clock pin, including a data net used as a clock elsewhere or a gated clock read by the reset; RDC-007 does not compare that clock net's own domain with the receiving domain, and RDC-009 remains the only finding.

### RDC-008
- **Trigger:** a reset net R with no register behind it whose combinational fan-in walk reaches at least two reset-like leaves and no data leaf, with at least one non-exact combinational edge on the way. Reset-like leaves: asynchronous reset roots, top inputs the shared classifier takes as KNOWN resets (ANALYSIS.md: `rst_n`, `por_rst_n`, `rst_lc_n`), and outputs of recognised reset synchronisers. Data leaves: other register outputs and top inputs that are DATA. A top input of UNDECIDED identity (`rst_q`) is a third kind of leaf.
- **Severity:** WARNING, Heuristic when the combination is classified: every direct combinational input of R is a true-polarity And or Or edge (no inversion, no other operator), all of one kind, over at least two distinct sources, and some user resets on R; WARNING, Unresolved otherwise.
- **Unknown:** an undriven, black-box, cyclic or X/Z operand in the selected bit's fan-in (an X/Z literal reaches a bit only through its own bit: part selects, bitwise operators, sized literals; not an X through a parameter, an always_comb assignment, a child port actual, or sign extension of a short signed literal, and a combinational loop in the cone is not Unresolved here), a mixed AND/OR tree (also when split across wires) and contradictory source or receiver polarity each give WARNING, Unresolved. Unclassified combinations (including nested or mixed expressions) are Unresolved; a top input that is DATA is a data leaf, so such a net is RDC-009 instead. With an UNDECIDED leaf and no data leaf, whether R combines resets or is gated is not decided: RDC-008 (when at least two sources) and RDC-009 are both WARNING, Unresolved, naming the leaf. Limit: a packed XOR/XNOR with a per-bit constant mask on a reset vector is treated as a multi-bit combination and may warn.

### RDC-009
- **Trigger:** a logic-built reset net R with no register behind it whose combinational fan-in walk (as RDC-008) reaches at least one data leaf and at least one non-exact combinational edge. Also a top-level output bit, used by no asynchronous pin of this design (itself or through exact copies), whose combinational fan-in reaches an asynchronous reset root, a KNOWN reset input or a recognised reset synchroniser and a data leaf through at least one non-exact edge: the reset is exported and its consumer is outside the design. A plain or inverted copy of the reset has no data leaf and is not reported. The output is also skipped when a forward exact or inverted copy of it reaches an asynchronous pin of this design (it is analysed as an internal root). Limit: an output whose name carries no reset word and that combines a single reset with functional signals is treated as a reset-qualified data output and not reported (e.g. `valid_o = rst ? 1'b0 : q`, `rst_n & din` to a data-named port); a scan-mux select on an exported reset is reported Unresolved, as for internal resets; a reset word followed by a request or status word (`rst_req_o`, `reset_done_o`) is treated as data.
- **Severity:** WARNING, Heuristic; WARNING, Unresolved for an exported reset ("exported reset built by logic; consumer outside the design", marks reset-extraction INCOMPLETE), except WARNING, Heuristic (no INCOMPLETE marker) when every functional leaf is a register output and one of them reaches the output as the select of a multiplexer whose data arms carry reset leaves (the select is binate, both polarities; a multiplexer that only chooses between data registers does not qualify); a top-level or scan-mode select and a unate gate (AND/OR) stay Unresolved; WARNING, Unresolved when the only candidates are UNDECIDED leaves (see RDC-008), or when a gate with no data leaf has an undriven, black-box, cyclic or X/Z operand in its fan-in. When a data gate also has such an incomplete fan-in, its Heuristic finding stays and an extra WARNING, Unresolved finding is added.
- **Unknown:** glitch freedom is not decided from RTL; what the exported reset's consumer needs is not known; X through a parameter, an always_comb assignment, a child port actual, or sign extension of a short signed literal, and a combinational loop in the cone, are not detected; each data-leaf register whose assertion sources differ from those of the users, or whose clock is unidentified, also gets RDC-017 (WARNING, Heuristic). A function result that ignores an argument still counts that argument.

### RDC-010
- **Trigger:** a register bit s with no asynchronous reset that assigns it a constant and no synchronous reset candidate, in the fan-in cone of a register bit d that has an asynchronous reset, with s and d in the same module instance path; one per (s symbol, d symbol).
- **Exempt:** s with an asynchronous reset that assigns it a constant; s and d in different instances.
- **Severity:** WARNING, Heuristic; WARNING, Unresolved when the asynchronous reset value of s is undecided (an X/Z, non-constant, or conditional forced value from a nested `if`/`case`, compound guard, or multiply-driven guard), since s is then neither held nor reset.
- **Unknown:** decided on the model (an undecided forced value marks scope reset-extraction INCOMPLETE). A function result that ignores an argument still counts the argument. Synchronous reset candidates are recognised by shape only (leading `if (s)` or trailing else-free `if (s)` constant-override suffix; a tied-inactive candidate still exempts; case-form and else-arm synchronous resets are not candidates).

### RDC-011
- **Trigger:** the design has more than one distinct non-tied asynchronous reset assertion leaf source (each async reset traced through recognised synchronisers, exact/inverted copies, and 1-bit constant XOR/XNOR polarity adapters; constant-tied resets are not counted as sources); one diagnostic per design, listing the counted sources in `signals` and `evidence`. A `reset_contracts` clause counts as covering a source only when its status is `Bound`, `Assumed`, or `Established` (not `Conflict` or `Unapplied`) and it relates that source to another counted source.
- **Severity:** INFO, Heuristic (trust model) when no interaction remains: no register bit carries asynchronous controls from two counted sources; every sampling between registers reset by different sources is exempt (RDC-004 reset propagation, or an RDC-005 exemption), so no RDC-004/RDC-005 finding remains; no counted source is read functionally by a register it does not reset (an RDC-019 use counts as an interaction), and no primary output's combinational cone reaches registers or reset inputs of two sources (a black box, a cone beyond the search budget, and a counted source that is not a primary input, such as a register, logic or black-box generated reset, count as an interaction). When every pair of sources has a declared group or release order, the INFO keeps "(declared by the environment, not checked)". Otherwise WARNING, Unresolved. Applicable active `reset_contracts` clauses are cited as evidence and never change the severity.
- **Unknown:** the WARNING is the explicit marker: scope reset-extraction INCOMPLETE; the sequencing of the sources is not decided. The INFO does not mark the scope INCOMPLETE. Limits: a combinational/logic-combined reset counts as one source; a black-box-only reset counts as one source; sources are traced through recognised reset synchronisers (any register chain reset by the source).

### RDC-012
- **Trigger:** the design has at least one asynchronous reset assertion source; one diagnostic per design. No power intent (UPF/CPF) is read; a design with only synchronous resets emits nothing.
- **Severity:** WARNING, Unresolved without a `power_intent` declaration. INFO, Informational with a trust model when the configuration declares `power_intent.model = single_always_on` (the only value; any other value or field is a configuration error): one always-on power domain with no retention, isolation or power switching is assumed, not checked. The declaration is recorded in the report input `power_intent`.
- **Unknown:** without the declaration, scope reset-extraction is INCOMPLETE (the marker applies only when RDC-012 runs) and no retention or isolation rule is evaluated. With it, no marker is raised. The declaration is the user's reviewed claim; UPF and CPF are not read. An asynchronous reset whose forced value is not decided (`case (rst_n)`, a guard that disagrees with the event edge, or one control listed on both edges) marks reset-extraction INCOMPLETE with that reason; the reset is still reported.

### RDC-013
- **Trigger:** each distinct asynchronous reset assertion source of the design (the traced root, after tracing through recognised synchronisers, bounded at 64 hops); one per source.
- **Severity:** WARNING, Informational; proof NOT_ATTEMPTED (a physical obligation RTL cannot show); WARNING, Unresolved for a source beyond the 64-hop bound. Each finding names its reset root in `signals`. Closure: a reviewed waiver narrowed to the reset root (rule and signal), with the STA or sign-off evidence for recovery, removal and pulse width in its reason. No configuration declaration changes the severity.
- **Unknown:** recovery/removal timing, minimum pulse width and metastability are not decided; never reported as safe. An asynchronous reset whose forced value is not decided marks reset-extraction INCOMPLETE with that reason; the reset is still reported. Limit: obligation accounting across packed bits can share one message with a count for distinct packed roots.

### RDC-014
- **Trigger:** a reset root R that is the output of a register (through exact alias edges only) with asynchronous register users, where that register's chain is not a recognised reset synchroniser.
- **Exempt:** R driven by a recognised reset synchroniser of any depth (RDC-006 covers shallow ones).
- **Severity:** WARNING, Heuristic; proof NOT_ATTEMPTED; WARNING, Unresolved for a chain longer than the chain analysis limit.
- **Unknown:** the pulse width of a register-driven reset is unproved; glitch freedom is a proof obligation (NOT_ATTEMPTED). Limit: a constant-dominated multiply driven wired net (`wand`) warns for a driver that cannot change the resolved reset level.

### RDC-016
- **Trigger:** a non-final stage of a recognised reset synchroniser (the first stage included) with an out-edge (walking through exact non-control combinational copies such as wires and instance port boundaries) other than the Seq edge into the next stage, i.e. another register, an asynchronous reset pin, a primary output, a black box, a clock root, or logic; one per stage.
- **Severity:** WARNING, Established.
- **Unknown:** none: decided on the model.

### RDC-017
- **Trigger:** a data-leaf register (select or gate) of a logic-built reset net (the RDC-009 case) whose assertion-source set differs from the sources of any one of the reset's other users (each receiver compared on its own; the select register itself excluded; one finding per select listing the receivers), or whose clock is unidentified, or whose reset has a source with no modelled driver even when the sets match; top-level selects are not checked.
- **Severity:** WARNING, Heuristic; WARNING, Unresolved when the select's clock or reset source has no modelled driver (undriven, tied or black box).
- **Unknown:** decided on the model; a select from another domain is reported, not shown glitch-free. Limits: clock-domain equality and opposite edges on equal reset nodes are outside the trigger (equal source sets with two resolved clocks are silent; RDC-009 still reports the gate); an inverted copy of a source is identified with the source; receiver evidence names a packed bit without its index (`q[2]` is shown as `q`).

### RDC-019
- **Trigger:** an asynchronous reset root bit R (judged per bit for packed reset vectors) with at least one out-edge that is neither an AsyncCtl edge nor a pure bit move: a Seq edge (data input, synchronous-reset or enable condition) or a non-exact Comb edge; one per R. The walk follows exact moves (wire copies, packed bit moves, known child-port connections) from R to its first functional use; a net with another driver is not followed. The finding's `signals` lists R and the first functional user register(s) (or combinational target) of each functional out-edge.
- **Exempt:** R used only as asynchronous reset pins, directly or through exact or inverted copies, or through a 1-bit constant XOR/XNOR polarity adapter (`rst_n ^ 1'b1`, `rst_n ^ ACTIVE_LOW`, `rst_n ~^ 1'b0`, `rst_n ^ 1'b0`, `rst_n ~^ 1'b1`, in wire assignments, port actuals, or child instances), that reach only such pins; R sampled as data only by the first stage of a recognised CDC data synchroniser (direct or inverted exact sole data input, deliberate resynchronisation of a reset level); when R (or its copy root) is a top-level input with an applied, unrejected `set_input_delay` whose effective contracts all declare a clock `Same` as domain C and which is not covered by a `set_false_path` or `set_multicycle_path` with `-from` or `-through` (same input-delay trust model as RDC-003), functional uses of R (synchronous reset or data) whose consumers are all clocked in domain C (uses in other domains, or escaping to primary outputs or black boxes, still report); a sibling lane of a packed vector that is never an asynchronous reset. A reset reaching only a primary output has no modelled external consumer and is not classed as functional. A `-to` exception on the receiving registers, and `-from [get_clocks C]` where C is the input-delay clock, are not considered. A `-through` on the reset port is treated as covering the port even when its `-from`/`-to` restrict it to other paths (conservative WARNING). A `-through` on a net that is a logic function of the reset, not an exact or inverted copy, is not matched; the input-delay trust is kept. A `-from` or `-through` selector is matched against every node on the input's exact-copy chain, including internal nets and the child-port pin the reset enters.
- **Severity:** WARNING, Heuristic.
- **Unknown:** a clear/set mix of one net across registers is not evaluated. Limit: a packed XOR/XNOR with a per-bit constant mask on a reset vector, or a wide constant XOR/XNOR truncated to 1 bit (`rst ^ 2'b10`), is treated as a multi-bit combination and may warn.

### RDC-020
- **Trigger:** a register symbol (hierarchical name, all bits) with some bits having an asynchronous reset that assigns them a constant and some bits having neither such a reset nor a synchronous reset candidate; one per symbol.
- **Exempt:** symbols with no unreset bit, or with no asynchronously reset bit.
- **Severity:** WARNING, Heuristic when an unreset bit has an out-edge to logic or a register, drives an asynchronous control, or is itself a primary output; INFO, Heuristic otherwise; WARNING, Unresolved when some bits have an undecided asynchronous reset value (an X/Z, masked-X, non-constant, or conditional forced value from a nested `if`/`case`, compound guard, or multiply-driven guard), since the partial reset is then not established. Limit: explicit non-constant data in a reset branch leaves that bit undecided, so the same applies.
- **Unknown:** decided on the model (an undecided forced value marks scope reset-extraction INCOMPLETE). A function result that ignores an argument still counts the argument. Synchronous reset candidates are recognised by shape only (leading `if (s)` or trailing else-free `if (s)` constant-override suffix; a tied-inactive candidate still exempts; case-form and else-arm synchronous resets are not candidates).

### RDC-023
- **Trigger:** either (a) a Gray-coded FIFO pair: two CDC crossing groups in the same hierarchy, both with Gray-coded pointers, running in opposite directions; (b) a handshake with unique reciprocal endpoints, an ambiguously paired reciprocal handshake candidate across elaborated hierarchy, or a candidate/grouped endpoint search that runs out of work or encounters an unknown cone before it can determine pairing; or (c) a recognised toggle synchroniser (CDC-014 with an edge detector) whose source, synchronizer stage or detected delayed stage is reset (an asynchronous root or the synchronous-reset candidate); one per structure.
- **Severity:** WARNING, Unresolved for every recognised FIFO pair and handshake (including ambiguous, search-incomplete or uncertain candidate pairs; a shared reset of the two pointers does not order the release of the two domains); proof NOT_ATTEMPTED. (b) INFO, Heuristic with a trust model when both endpoints and every synchroniser stage in both directions are asynchronously reset (and by no synchronous reset) from one assertion leaf with one polarity, traced through recognised reset synchronisers and exact/inverted copies, and all of them reset to the same binary value, so the compared request and acknowledge values agree while idle; an ambiguous pairing qualifies only when every candidate pair meets this. A search that runs out of work stays WARNING, Unresolved. Limit: only endpoint and synchroniser-stage registers are checked; the trust model that neither side requests before both domains have left reset is not checked. (c) WARNING, Unresolved when the source, required synchronizer stages and detected delayed stages are not all reset by the same signals (matching reset kind and polarity), since a one-sided or unreset delayed stage can create or lose an event. Reset values through each detected delayed stage are checked independently of detector observability. Unequal or unknown asynchronous reset values or unequal or unknown values under a shared synchronous reset give WARNING Unresolved. INFO Heuristic with a trust model when the reset signals agree and the compared values leave no open mismatch. Proof NOT_ATTEMPTED. Applicable `reset_contracts` clauses are cited as evidence and never change the severity.
- **Unknown:** the reset release order is an obligation, not decided (proof NOT_ATTEMPTED).

### RDC-024
- **Trigger:** an output of a recognised CDC synchroniser (its stage at the required depth or a follower; chain depth >= 2, no logic between stages, any width) whose combinational fan-out reaches an asynchronous reset pin of a register; one per synchroniser chain, however many of its stages the reset reads.
- **Severity:** WARNING, Heuristic; proof NOT_ATTEMPTED. Applicable `reset_contracts` clauses are cited as evidence and never change the severity.
- **Unknown:** none decided: the request/acknowledge completion and the reset release ordering are a proof obligation.

### RDC-025
- **Trigger:** a top-level output bit whose combinational fan-in (walk stops at registers) reaches a register bit with neither an asynchronous reset that assigns it a constant nor a synchronous reset candidate; one per output name (first found).
- **Exempt:** outputs whose register sources are all reset.
- **Severity:** WARNING, Heuristic; WARNING, Unresolved when the path reaches a register, the output's own register included, whose asynchronous reset value is undecided (non-constant, conditional under a nested `if`/`case` whose arms do not all force the same constant, a non-constant loop bound, an AND-combined or non-reset-implied guard, or a multiply-driven guard, unanalysed, X or Z; constant-bound `for` and fixed-size `foreach` reset loops are unrolled, elaboration-constant/parameter conditions are folded, and an OR-combined guard implied true by asserting the reset such as `!rst || other` or `rst || other` is decided).
- **Unknown:** decided on the model (an undecided forced value marks scope reset-extraction INCOMPLETE). A function result that ignores an argument still counts the argument. Synchronous reset candidates are recognised by shape only (leading `if (s)` or trailing else-free `if (s)` constant-override suffix; a tied-inactive candidate still exempts; case-form and else-arm synchronous resets are not candidates; limit: a conjunctive guard such as `if (rst && e)` is accepted as a synchronous reset candidate on shape alone, even though assertion requires every conjunct to hold). Valid-qualification of unreset payload outputs (for example, an unreset AXI-Stream payload register qualified by a reset `TVALID` output of the same interface) is not analysed, so such payload outputs remain reported.

### RDC-026
- **Trigger:** a register bit with two or more asynchronous controls, judged per bit; one per register symbol, at its first such bit. Each control of a bit is classified by the value it forces on that bit: clear, set, or unknown (not a constant). Exact aliases of one source with one polarity are one control. A control counts as unconditional only when every path through its branch forces the bit; a branch that conditionally holds the bit or falls through is Unresolved. A branch is conditional for a register when a test on a signal other than the block's own controls applies to the branch and is not implied true by asserting the control (an OR-combined guard `!rst || other` is decided; an AND-combined guard `!rst && mode` is conditional), or when a runtime test nested in the branch has arms that disagree or omit the bit (elaboration-constant conditions are folded, and a nested `if`/`case` whose every arm forces the same constant to the bit is decided; a nested test on another register does not downgrade this register); an enable evaluated only after all controls are inactive does not make it conditional. Exact copies of one net listed on the same edge are one control with its known forced value.
- **Severity:** WARNING, Established when some bit has both an unconditional clear and an unconditional set control (proof NOT_ATTEMPTED); WARNING, Unresolved when a control forces an unknown value on some bit or is conditional; INFO, Heuristic otherwise (no bit mixes clear and set, and no control is unknown).
- **Unknown:** an unknown forced value marks scope reset-extraction INCOMPLETE; priority and simultaneous-assertion scenarios are not evaluated. Limits: inverted aliases on opposite edges (`negedge inv` with `wire inv = ~rst_n`) are reported as two controls; a dual-edge reset listed through exact copies reports one receiver with an unknown forced value, and redundant dual-edge spellings are unsupported.

### RDC-027
- **Trigger:** an SDC set_false_path or set_multicycle_path whose from or through list matches an asynchronous reset root (an exact bit selector such as `rst_n[3]` matches that bit; `get_clocks X` matches a clock object X whose source is the root (one port may carry several clocks), not a port named X; a create_clock without -add replaces the earlier clocks on each resolved elaborated source bit regardless of selector spelling — qualified, unqualified, glob or bus wildcard — so an exception naming a replaced clock covers nothing on that bit); one per (exception, reset root), with the bit named by its declared index.
- **Exempt:** exceptions that name the reset only in a to list; set_max_delay and set_min_delay; a `set_false_path` (with no `-through`) whose `-from` names only synchroniser-only reset input bit(s) with no functional use (same condition as RDC-002; a clock use of the input is not counted as a functional use here — CST-011 reports an unconstrained clock).
- **Severity:** WARNING, Established.
- **Unknown:** none: a false path removes timing checks and a multicycle path changes the timing relationship; neither proves reset safety, and the finding says so. Limits: regexp selectors and through-pin selectors are accepted only as far as the SDC reader interprets them; duplicate SDC clock names on distinct targets keep the earlier target.

### RDC-028
- **Trigger:** either (a) an asynchronous reset root used active-low by some register bits and active-high by others, or (b) a logic-built reset root R reached from exactly one leaf (register output or top input) through combinational edges, with at least one non-exact edge on the walk, where every direct combinational input of R is inverted (`inv` = 1); port connections carry the actual's polarity, so an inverted actual (such as `~rst_n`) is an inverted input; one per root and form.
- **Exempt:** logic-built resets with several leaves (RDC-008, RDC-009).
- **Severity:** ERROR, Established for (a); INFO, Heuristic for (b), claimed only for exact single-leaf forms (`~x`, `!x` of one bit, `x ^ 1'b1` or `x ^ P` with a parameter P, `x ~^ 1'b0`, a selected bit such as `a[1]`, also through exact copies; a logical not of a multibit operand only when it holds no constant bit); WARNING, Unresolved when an input has no modelled driver or an X/Z literal in its fan-in.
- **Unknown:** (b) does not read the polarity assumptions of the receiving blocks, and does not establish the downstream interpretation of polarity. X through a parameter, an always_comb assignment or a child port actual, and a combinational loop in the cone, are not detected. Limit: a packed XOR/XNOR with a per-bit constant mask on a reset vector, or a wide constant XOR/XNOR truncated to 1 bit (`rst ^ 2'b10`), is treated as a multi-bit combination and does not report per-bit inversions or copies.

### RDC-029
- **Trigger:** (no implementation in this build)
- **Exempt:** -
- **Severity:** -
- **Unknown:** -

### RDC-030
- **Trigger:** a recognised reset synchroniser whose stages carry ASYNC_REG, sverity_sync or cdc_sync (case-insensitive) on some but not all stages (any profile), or on none of them under profile fpga.
- **Exempt:** no attribute on any stage under the asic or generic profile; an unrecognised chain (RDC-003).
- **Severity:** WARNING Established.
- **Unknown:** attributes are read from the RTL symbols only, and the result does not depend on attribute order. An attribute whose value is X, Z or not constant is WARNING, Unresolved. A marker of unsupported type (real, shortreal) is Unresolved even when it is a known constant; independent asserted markers still establish marking, and unrecognised synchroniser shapes are out of scope.
