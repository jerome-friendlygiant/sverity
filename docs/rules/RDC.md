# RDC - Reset-domain crossings, asynchronous reset behavior and coordination

Titles must match `catalog.json` (a unit test checks this). Specification bullets are the contract each rule is tested against
(`tests/fixtures/<RULE-ID>/`). Reset recognition is structural; physical properties (recovery/removal, pulse width, glitches) and power intent
are explicit obligations/unknown markers, never "safe". Reset roots are traced through recognised reset synchronisers to their assertion source.

| ID | Required check |
|---|---|
| `RDC-001` | Identify reset sources, polarity, synchronous/asynchronous nature |
| `RDC-002` | Unconstrained or unknown reset source / domain |
| `RDC-003` | Asynchronous reset deassertion not synchronized to receiving clock |
| `RDC-004` | Data crosses between different reset domains on the same clock |
| `RDC-005` | Data crosses between independently reset domains on different clocks |
| `RDC-006` | Reset synchronizer has too few stages or logic between stages |
| `RDC-007` | Reset generated by a register or logic in another clock/reset domain |
| `RDC-008` | Reset reconvergence: combined or conditional reset topology, including reconvergence after independent release |
| `RDC-009` | Reset gating/muxing that may glitch |
| `RDC-010` | Register partially reset while feeding other reset-sensitive logic |
| `RDC-011` | Unmodeled reset sequencing dependency |
| `RDC-012` | Retention/isolation/power-intent reset rules |
| `RDC-013` | Analog recovery/removal, minimum reset pulse width and physical metastability |
| `RDC-014` | Reset assertion glitch or pulse-width risk |
| `RDC-016` | Reset synchronizer stage fanout to logic |
| `RDC-017` | Reset mux/gate select from different reset domain |
| `RDC-019` | Reset fanout into functional asynchronous set/clear controls |
| `RDC-020` | Partial reset of packed state and dependent control |
| `RDC-023` | FIFO and handshake reset release sequencing |
| `RDC-024` | Reset request/acknowledge sequencing across domains |
| `RDC-025` | Interface outputs during only one side reset |
| `RDC-026` | Several asynchronous controls on one register (set and reset, power-on and functional) |
| `RDC-027` | Reset-domain false-path exception does not imply safety |
| `RDC-028` | Reset polarity and synchronization assumptions across hierarchy, including one reset used with both polarities |
| `RDC-029` | Retention or isolation reset boundaries when power intent provided |

## Specification

- **RDC-001** — every asynchronous reset root (polarity from the event edge, source kind) and every synchronous reset candidate (polarity from the condition shape). Exempt: none. Severity: INFO per reset; WARNING (Unresolved) when the root is not a primary input. Unknown: scope reset-extraction INCOMPLETE.
- **RDC-002** — a reset input that no exception/constraint names. Exempt: none. Severity: WARNING (Unresolved). Unknown: scope reset-extraction INCOMPLETE.
- **RDC-003** — per (reset root, clock domain): straight from a primary input, from logic, from black box/undriven (WARNING Unresolved); recognised reset synchroniser (INFO + trust model). Exempt: none. Severity: WARNING / INFO. Unknown: never INFO unless the structure is recognised.
- **RDC-004** — same clock: a register that can be reset asynchronously feeds a register not reset by the same assertion source. Exempt: same assertion source after reset synchronisers. Severity: WARNING (heuristic), proof NOT_APPLICABLE obligation text. Unknown: n/a.
- **RDC-005** — as RDC-004 across clocks that are not Same (the data crossing itself is CDC). Exempt: same assertion source. Severity: WARNING (heuristic). Unknown: n/a.
- **RDC-006** — recognised reset synchroniser (every stage async-reset, same clock, constant first D) with fewer than RDC-006.min_stages stages; logic or several sources on a stage. Exempt: none. Severity: WARNING. Unknown: unrecognised structure -> RDC-003 WARNING.
- **RDC-007** — a reset generated by a register (or logic) in a clock domain that is not Same as its users. Exempt: none. Severity: ERROR (declared asynchronous), WARNING (UNKNOWN), INFO (exclusive). Unknown: Unresolved when the relation is UNKNOWN.
- **RDC-008** — a reset net built by logic from >= 2 reset-like sources (asserts on either, releases after the last). Exempt: none. Severity: WARNING (heuristic). Unknown: primary inputs count as reset-like when named rst/reset (heuristic).
- **RDC-009** — a reset net gated or multiplexed by functional signals. Exempt: none. Severity: WARNING (heuristic); glitch freedom is not provable from RTL. Unknown: n/a.
- **RDC-010** — an unreset register feeding a reset register of the same module instance. Exempt: none. Severity: WARNING (heuristic). Unknown: n/a.
- **RDC-011** — more than one independent asynchronous reset assertion source: sequencing is not modelled. Exempt: none. Severity: WARNING (Unresolved), scope reset-extraction INCOMPLETE. Unknown: this rule is the explicit incompleteness marker.
- **RDC-012** — reset exists but no power intent is supported or supplied. Exempt: none. Severity: WARNING (Unresolved). Unknown: scope reset-extraction INCOMPLETE; no retention/isolation rule is evaluated.
- **RDC-013** — every reset assertion source: recovery/removal and minimum pulse width are physical obligations. Exempt: none. Severity: INFO, proof NOT_ATTEMPTED. Unknown: never claimed safe.
- **RDC-014** — a reset driven by a data register that is not a reset synchroniser. Exempt: recognised synchronisers. Severity: WARNING (heuristic), proof NOT_ATTEMPTED. Unknown: combinational resets are RDC-009.
- **RDC-016** — a non-final stage of a recognised reset synchroniser also feeds other logic. Exempt: none. Severity: WARNING. Unknown: n/a.
- **RDC-017** — the select/gate of a combinational reset comes from a register in another reset domain or with an unidentified clock. Exempt: none. Severity: WARNING (heuristic). Unknown: n/a.
- **RDC-019** — an asynchronous reset signal that also feeds data or a synchronous reset in other registers; or one reset net acting as asynchronous clear on some registers and as asynchronous set on others. Exempt: none. Severity: WARNING. Unknown: n/a.
- **RDC-020** — a vector whose bits are partly reset: WARNING when the unreset bits feed other logic, INFO otherwise. Exempt: none. Severity: WARNING / INFO (heuristic). Unknown: n/a.
- **RDC-023** — recognised Gray FIFO pair or req/ack handshake: the reset release order of the two domains is an unverified obligation. Exempt: none. Severity: WARNING (Unresolved), proof NOT_ATTEMPTED. Unknown: n/a.
- **RDC-024** — a control synchronised into a domain and used there as an asynchronous reset (reset request/acknowledge). Exempt: none. Severity: WARNING (heuristic), proof NOT_ATTEMPTED. Unknown: n/a.
- **RDC-025** — a primary output that depends on a register without any reset. Exempt: none. Severity: WARNING (heuristic). Unknown: n/a.
- **RDC-026** — a register with more than one asynchronous control (the whole if / else-if chain is read): both set and clear = WARNING (simultaneous assertion undefined, priority = chain order); several controls forcing the same value (power-on + functional) = INFO. Exempt: none. Severity: WARNING / INFO. Unknown: a non-constant reset value -> Unresolved WARNING and scope reset-extraction INCOMPLETE.
- **RDC-027** — set_false_path / set_multicycle_path starting at or through a reset. Exempt: none. Severity: WARNING (the exception never makes a reset crossing safe). Unknown: n/a.
- **RDC-028** — one reset net used both active-low and active-high (ERROR); a reset that is a logic function of a single other signal (INFO, check polarity/synchronisation). Exempt: none. Severity: ERROR / INFO. Unknown: n/a.
- **RDC-029** — reset exists but no power intent is supported or supplied (retention/isolation reset boundaries). Exempt: none. Severity: WARNING (Unresolved). Unknown: scope reset-extraction INCOMPLETE.
