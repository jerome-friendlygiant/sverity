# RDC - Reset-domain crossings, asynchronous reset behavior and coordination

Titles must match `catalog.json` (a unit test checks this). Specification bullets are the contract each rule is tested against
(`tests/fixtures/<RULE-ID>/`). Reset recognition is structural; physical properties (recovery/removal, pulse width, glitches) and power intent
are explicit obligations/unknown markers, never "safe". Reset roots are traced through recognised reset synchronisers to their assertion source.

| ID | Required check |
|---|---|
| `RDC-001` | Reset-source inventory and registers without an identified reset root |
| `RDC-002` | Reset input with no constraint (unknown reset source) |
| `RDC-003` | Asynchronous reset deassertion not synchronized to receiving clock |
| `RDC-004` | Data crosses between different reset domains on the same clock |
| `RDC-005` | Data crosses between independently reset domains on different clocks |
| `RDC-006` | Reset synchronizer has too few stages or logic between stages |
| `RDC-007` | Reset generated by a register or logic in another clock/reset domain |
| `RDC-008` | Reset net combined from two or more reset sources |
| `RDC-009` | Reset gating/muxing that may glitch |
| `RDC-010` | Unreset register feeding a reset register of the same module instance |
| `RDC-011` | Several independent asynchronous reset sources: sequencing not modelled |
| `RDC-012` | Power intent not supplied: retention and isolation resets are not evaluated |
| `RDC-013` | Recovery, removal and minimum pulse width obligation for every asynchronous reset |
| `RDC-014` | Asynchronous reset driven by a data register that is not a reset synchroniser |
| `RDC-016` | Reset synchronizer stage fanout to logic |
| `RDC-017` | Reset mux/gate select from different reset domain |

## Specification

### RDC-001
- **Trigger:** each asynchronous reset root R (the traced root node of a register's async reset event, any clock domain), polarity from the event edge (negedge = active-low; the last register bit seen for R is used), source kind TopPort, Logic, BlackBox, Undriven or Cycle; plus each synchronous reset candidate signal (top-level `if (s)` whose branch only assigns constants).
- **Severity:** INFO (Informational) per R; WARNING (Unresolved) per R that is not a TopPort; INFO (Heuristic) per synchronous candidate.
- **Unknown:** the WARNING marks scope reset-extraction INCOMPLETE; the synchronous candidate is a heuristic on the condition shape.

### RDC-002
- **Trigger:** (a) a top-level input bit R that is an asynchronous reset root and is not named in the from, through or to list of any SDC path exception (any kind); one per R. Input delays and clock definitions are not consulted. (b) a top-level input bit that is the synchronous-reset candidate of a register and not an asynchronous root, with no `set_input_delay` naming it; one per input, at the first register it resets.
- **Exempt:** (a) R named by any path exception in any of its three lists; (b) an input named by any input delay.
- **Severity:** WARNING, Unresolved.
- **Unknown:** the WARNING marks scope reset-extraction INCOMPLETE (the timing relation of R to the domains it resets is unknown).

### RDC-003
- **Trigger:** (a) each (asynchronous reset root R, clock domain D) with register bits in D reset by R, where R is a top-level port, a black box, undriven or cycle output, combinational logic with no register behind it, the output of a register with unidentified clock, or the output of a register clocked in D that is not a recognised reset synchroniser (a chain of nonblocking registers with established assertion/release assignments: all stages asynchronously take the binary asserted level required by downstream reset polarity, share the same raw reset sources and polarities and clock edge, the first stage takes the opposite binary released constant, each later stage takes exactly its predecessor, depth >= RDC-006.min_stages, default 2). Registers clocked in another domain are RDC-007; shallower recognised chains are RDC-006. (b) each register symbol with an asynchronous reset and no identified clock, one per name.
- **Exempt:** the stage registers of a recognised synchroniser fed by a top-level reset (they take the raw reset by design); under (a), register bits with unidentified clock are skipped (CST-004 reports their paths; (b) reports them).
- **Severity:** INFO (Informational, proof NOT_ATTEMPTED) for a recognised synchroniser in (a); WARNING (Unresolved) for every other case of (a) and for (b).
- **Unknown:** every WARNING marks scope reset-extraction INCOMPLETE; the INFO records the trust model and never claims recovery/removal safety.

### RDC-004
- **Trigger:** a register bit d and a register bit s in d's fan-in cone (walk through Comb and Seq edges, stopping at registers), both in the same clock domain, where s has asynchronous reset sources rs (traced through recognised synchronisers) and rs is not a subset of the sources rd of d (rd may be empty); one per destination symbol and pair of reset sets, listing each source symbol as evidence. A waiver scoped by `signal` must name the destination or cover every source.
- **Exempt:** rs a subset of rd (d is reset by every source that resets s); bits with unidentified clock (CST-004).
- **Severity:** WARNING, Heuristic; proof NOT_ATTEMPTED.
- **Unknown:** none: decided on the model; the data crossing itself is a CDC question.

### RDC-005
- **Trigger:** as RDC-004 for s and d in different clock domains whose ClockRelations relation is not Same (Async, Exclusive or Unknown).
- **Exempt:** rs a subset of rd; relation Same; bits with unidentified clock (CST-004).
- **Severity:** WARNING, Heuristic (Exclusive gives WARNING here, not INFO); proof NOT_ATTEMPTED.
- **Meaning:** a reset-compatibility obligation, not proven destination corruption. Source assertion may change the transmitted value while the destination remains active. A data synchroniser reduces metastability; it does not prove the destination tolerates that functional change. No data-chain exemption or INFO trust model is inferred. Shared assertion sources are structurally covered; otherwise tolerance, masking and reset sequencing need protocol evidence.
- **Unknown:** destination tolerance is not proved; the obligation stays visible at WARNING with proof NOT_ATTEMPTED. The data crossing itself is a separate CDC question.

### RDC-006
- **Trigger:** a reset root R driven by a register chain in the users' clock domain that is a recognised reset synchroniser (see RDC-003) with depth < RDC-006.min_stages (floor 2, default 2); or a same-domain chain that is not recognised because a stage's D has logic or several sources.
- **Severity:** WARNING, Established for too few stages; WARNING, Heuristic for logic or several sources on a stage.
- **Unknown:** an unrecognised chain always also emits RDC-003 WARNING (Unresolved) and marks reset-extraction INCOMPLETE.

### RDC-007
- **Trigger:** a reset R generated by a register g in clock domain Dg, directly or by combinational logic with g among its register leaves, and used by register bits in domain Du where relation(Dg, Du) is not Same; for the logic form, one finding per leaf register, against the first user domain that differs.
- **Exempt:** relation Same (no finding).
- **Severity:** ERROR, Established for Async; INFO, Established for Exclusive; WARNING, Unresolved for Unknown.
- **Unknown:** an Unknown relation is WARNING Unresolved; the register-driven form also marks clock-relationships INCOMPLETE.

### RDC-008
- **Trigger:** a reset net R with no register behind it whose combinational fan-in walk reaches at least two reset-like leaves and no data leaf, with at least one non-exact combinational edge on the way. Reset-like leaves: asynchronous reset roots, top inputs whose name contains `rst` or `reset` (any case), and outputs of recognised reset synchronisers. Data leaves: other register outputs and other top inputs.
- **Severity:** WARNING, Heuristic when the combination is classified: every direct combinational input of R is a true-polarity And or Or edge (no inversion, no other operator), all of one kind, over at least two distinct sources, and some user resets on R; WARNING, Unresolved otherwise.
- **Unknown:** unclassified combinations (including nested or mixed expressions) are Unresolved; a top input not named like a reset is a data leaf, so such a net is RDC-009 instead.

### RDC-009
- **Trigger:** a logic-built reset net R with no register behind it whose combinational fan-in walk (as RDC-008) reaches at least one data leaf and at least one non-exact combinational edge.
- **Severity:** WARNING, Heuristic.
- **Unknown:** glitch freedom is not decided from RTL; each data-leaf register whose assertion sources differ from those of the users, or whose clock is unidentified, also gets RDC-017 (WARNING, Heuristic).

### RDC-010
- **Trigger:** a register bit s with no asynchronous reset and no synchronous reset candidate, in the fan-in cone of a register bit d that has an asynchronous reset, with s and d in the same module instance path; one per (s symbol, d symbol).
- **Exempt:** s with any reset; s and d in different instances.
- **Severity:** WARNING, Heuristic.
- **Unknown:** none: decided on the model.

### RDC-011
- **Trigger:** the design has more than one distinct asynchronous reset assertion source (each async reset traced through recognised synchronisers); one diagnostic per design.
- **Severity:** WARNING, Unresolved.
- **Unknown:** this is the explicit marker: scope reset-extraction INCOMPLETE; the sequencing of the sources is not decided.

### RDC-012
- **Trigger:** the design has at least one asynchronous reset assertion source; one diagnostic per design. No power intent (UPF/CPF) is read; a design with only synchronous resets emits nothing.
- **Severity:** WARNING, Unresolved.
- **Unknown:** this is the explicit marker: scope reset-extraction INCOMPLETE; no retention or isolation rule is evaluated.

### RDC-013
- **Trigger:** each distinct asynchronous reset assertion source of the design (the traced root, after tracing through recognised synchronisers); one per source.
- **Severity:** WARNING, Informational; proof NOT_ATTEMPTED (a physical obligation RTL cannot show).
- **Unknown:** recovery/removal timing, minimum pulse width and metastability are not decided; never reported as safe.

### RDC-014
- **Trigger:** a reset root R that is the output of a register (through exact alias edges only) with asynchronous register users, where that register's chain is not a recognised reset synchroniser.
- **Exempt:** R driven by a recognised reset synchroniser of any depth (RDC-006 covers shallow ones).
- **Severity:** WARNING, Heuristic; proof NOT_ATTEMPTED.
- **Unknown:** none decided: minimum pulse width and glitch freedom are a proof obligation (NOT_ATTEMPTED).

### RDC-016
- **Trigger:** a non-final stage of a recognised reset synchroniser (the first stage included) with an out-edge other than the Seq edge into the next stage, i.e. another register, an asynchronous reset pin or logic; one per stage.
- **Severity:** WARNING, Established.
- **Unknown:** none: decided on the model.

### RDC-017
- **Trigger:** a data-leaf register (select or gate) of a logic-built reset net (the RDC-009 case) whose assertion-source set differs from the union of the sources of the reset's users, or whose clock is unidentified; top-level selects are not checked.
- **Severity:** WARNING, Heuristic.
- **Unknown:** none: decided on the model; a select from another domain is reported, not shown glitch-free.

### RDC-019
- **Trigger:** an asynchronous reset root R with at least one out-edge that is neither an AsyncCtl edge nor a pure bit move: a Seq edge (data input, synchronous-reset or enable condition) or a non-exact Comb edge; one per R.
- **Exempt:** R used only as asynchronous reset pins.
- **Severity:** WARNING, Heuristic.
- **Unknown:** a clear/set mix of one net across registers is not evaluated.

### RDC-020
- **Trigger:** a register symbol (hierarchical name, all bits) with some bits having an asynchronous reset and some bits having neither an asynchronous reset nor a synchronous reset candidate; one per symbol.
- **Exempt:** symbols with no unreset bit, or with no asynchronously reset bit.
- **Severity:** WARNING, Heuristic when an unreset bit has an out-edge to logic or a register; INFO, Heuristic otherwise.
- **Unknown:** none: decided on the model.

### RDC-023
- **Trigger:** either (a) a Gray-coded FIFO pair: two CDC crossing groups in the same hierarchy, both with Gray-coded pointers, running in opposite directions; or (b) a handshake: two single-bit recognised synchronised crossings in the same hierarchy, in opposite directions, where the source register of each depends (fan-in) on the other crossing's synchroniser stages; one per pair; or (c) a recognised toggle synchroniser (CDC-014 with an edge detector) whose source or output stage is reset (an asynchronous root or the synchronous-reset candidate); one per toggle.
- **Severity:** WARNING, Unresolved for every recognised FIFO pair and handshake (a shared reset of the two pointers does not order the release of the two domains); proof NOT_ATTEMPTED. (c) WARNING, Unresolved when the source and the output stage are not reset by the same signals, since a one-sided reset creates or loses an event; INFO, Heuristic with a trust model when they are; proof NOT_ATTEMPTED.
- **Unknown:** the reset release order is an obligation, not decided (proof NOT_ATTEMPTED).

### RDC-024
- **Trigger:** an output of a recognised CDC synchroniser (its stage at the required depth or a follower; chain depth >= 2, no logic between stages, any width) whose combinational fan-out reaches an asynchronous reset pin of a register; one per synchroniser chain, however many of its stages the reset reads.
- **Severity:** WARNING, Heuristic; proof NOT_ATTEMPTED.
- **Unknown:** none decided: the request/acknowledge completion and the reset release ordering are a proof obligation.

### RDC-025
- **Trigger:** a top-level output bit whose combinational fan-in (walk stops at registers) reaches a register bit with neither an asynchronous reset nor a synchronous reset candidate; one per output name (first found).
- **Exempt:** outputs whose register sources are all reset.
- **Severity:** WARNING, Heuristic.
- **Unknown:** none: decided on the model.

### RDC-026
- **Trigger:** a register bit with two or more asynchronous controls, judged per bit; one per register symbol, at its first such bit. Each control of a bit is classified by the value it forces on that bit: clear, set, or unknown (not a constant).
- **Severity:** WARNING, Established when some bit has both a clear and a set control (proof NOT_ATTEMPTED); WARNING, Unresolved when a control forces an unknown value on some bit; INFO, Heuristic otherwise (no bit mixes clear and set, and no control is unknown).
- **Unknown:** an unknown forced value marks scope reset-extraction INCOMPLETE; priority and simultaneous-assertion scenarios are not evaluated.

### RDC-027
- **Trigger:** an SDC set_false_path or set_multicycle_path whose from or through list matches an asynchronous reset root; one per (exception, reset root).
- **Exempt:** exceptions that name the reset only in a to list; set_max_delay and set_min_delay.
- **Severity:** WARNING, Established.
- **Unknown:** none: the finding states that the exception does not make the crossing safe.

### RDC-028
- **Trigger:** either (a) an asynchronous reset root used active-low by some register bits and active-high by others, or (b) a logic-built reset root R reached from exactly one leaf (register output or top input) through combinational edges, with at least one non-exact edge on the walk, where every direct combinational input of R is inverted (`inv` = 1); port connections carry the actual's polarity, so an inverted actual (such as `~rst_n`) is an inverted input; one per root and form.
- **Exempt:** logic-built resets with several leaves (RDC-008, RDC-009).
- **Severity:** ERROR, Established for (a); INFO, Heuristic for (b).
- **Unknown:** (b) does not read the polarity assumptions of the receiving blocks.

### RDC-029
- **Trigger:** (no implementation in this build)
- **Exempt:** -
- **Severity:** -
- **Unknown:** -

### RDC-030
- **Trigger:** a recognised reset synchroniser whose stages carry ASYNC_REG, sverity_sync or cdc_sync (case-insensitive) on some but not all stages (any profile), or on none of them under profile fpga.
- **Exempt:** no attribute on any stage under the asic or generic profile; an unrecognised chain (RDC-003).
- **Severity:** WARNING Established.
- **Unknown:** none; attributes are read from the RTL symbols only.
