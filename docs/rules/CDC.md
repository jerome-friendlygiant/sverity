# CDC - Clock-domain crossings and synchronizer/protocol structure

Titles must match `catalog.json` (a unit test checks this). Specification bullets are the contract each rule is tested against
(`tests/fixtures/<RULE-ID>/`, with mutations: `mut_*` is a defect injected into the neighbouring `good_*` design). Recognition is structural:
a recognised structure is INFO only when it states its trust model; the unproved functional obligation of a recognised protocol is a WARNING (CDC-024, proof NOT_ATTEMPTED), never "proven". Relationship UNKNOWN is never treated as safe.

**One crossing, one primary finding.** CDC-016, CDC-017 (counter or partly synchronised Gray), CDC-028, CDC-032 and CDC-003/004 can describe one crossing group. The most specific enabled rule, in that order CDC-017, CDC-032, CDC-028, CDC-016, CDC-004, CDC-003, is the finding; the others become `also_matches` evidence, the severity is the highest of them, and a description with Established confidence keeps the finding Established. Disabling the primary rule passes the crossing to the next one, so disabling one rule cannot hide it. Each enabled rule keeps its own decision: the finding takes the highest severity after overrides, and it is waived only when each has a waiver, or by its fingerprint, which names this exact finding.
Crossing severity: ERROR if the clocks are declared asynchronous, WARNING if UNKNOWN, INFO if exclusive.

## Specification

Terms: a crossing group is a (source signal, destination signal) pair; its width is its number of destination bits; its relation is the clock relation of the two domains (Same, Async, Exclusive, Unknown). Same groups are not crossings. A chain starts at destination register d and follows non-blocking same-domain registers that are each fed only by the previous stage; depth counts them (a library synchroniser counts its declared stages). Depth >= 2 with no link logic is a recognised synchroniser for the qualifier, protocol and input rules; the crossing classes compare depth with CDC-005.min_stages (default 2, never below 2).

### CDC-001
- **Trigger:** each sequential block with a register bit whose clock is not identified (not exactly one clock edge event once the events tested by the top if-chain are removed), each `always_latch` procedure (ProcKind Latch), and one INFO per clock domain with its register-bit count.
- **Severity:** WARNING Unresolved for unidentified blocks and latches; INFO Informational per domain (proof NOT_APPLICABLE).
- **Unknown:** unresolved clock also records CST-010 `unresolved-clock`; scope clock-extraction INCOMPLETE. `always @*` latches are procedures of kind Comb and are not reported here.

### CDC-002
- **Trigger:** each clock domain whose root (traced through exact aliases and through pairs of one-bit inversions, `~~clk`, as in a generic clock buffer; a collapsed wide node is never an inversion, and delays such as `assign #2` are not modeled, as synthesis ignores them) is not a top-level input port: logic-generated, black-box output, cyclic or undriven. A clock driven by a modeled register is logic-generated even when the graph omits its self-feedback edge. A clock gated through an unmodelled black box also gets CDC-002.
- **Severity:** WARNING Unresolved.
- **Unknown:** the domain's relation to other clocks stays UNKNOWN (CST-004 per pair); scope clock-extraction INCOMPLETE.

### CDC-003
- **Trigger:** a single-bit crossing group (s -> d, relation not Same) where d starts no chain of depth >= 2 without link logic (unsynchronised) and d is not a qualified payload (CDC-039).
- **Exempt:** qualified payloads and undecided capture qualification (CDC-039). A recognised synchroniser (depth >= min_stages, no link logic, first stage without fan-out) is INFO, not a finding class change.
- **Severity:** ERROR Established when Async; WARNING Unresolved when Unknown; INFO Informational when Exclusive or recognised (proof NOT_ATTEMPTED). This is the severity convention used by "as CDC-003" below.
- **Unknown:** Unknown relation is WARNING Unresolved, never INFO. An unidentified clock on either side emits no CDC-003; the path is counted as CST-004 (scope clock-relationships INCOMPLETE). Opaque effects on a candidate synchronizer stage leave the chain Unresolved and mark graph-precision INCOMPLETE. A known unsafe shallow capture or early tap still reports its structural hazard.

### CDC-004
- **Trigger:** a multi-bit crossing group (width >= 2, relation not Same) with at least one destination bit that starts no chain of depth >= 2 without link logic, and that is not a qualified payload (CDC-039). A wide symbol (a packed value over 131072 bits or an unpacked one over 16384 bits, tracked as one node) in a crossing is reported here without classification.
- **Exempt:** qualified payloads and undecided capture qualification (CDC-039). A group whose bits are all synchronised is decided by CDC-009, CDC-017 and CDC-018; a partly synchronised Gray pointer is reported here as well as by CDC-017.
- **Severity:** as CDC-003. Wide symbol: WARNING Unresolved, or ERROR Unresolved when Async and no next-stage register exists; INFO when Exclusive.
- **Unknown:** wide symbol: scope graph-precision INCOMPLETE and CST-010 wide-symbol fallback; Unknown relation as CDC-003. Opaque effects on a candidate stage leave that capture Unresolved and mark graph-precision INCOMPLETE. Known unsafe sibling captures still report their structural hazards.

### CDC-005
- **Trigger:** a register-launched or primary-input crossing (relation not Same) with a destination bit whose chain has depth >= 2, no link logic, and depth < CDC-005.min_stages.
- **Severity:** as CDC-003.
- **Unknown:** Unknown relation as CDC-003; none otherwise. When an opaque call can alter a candidate stage before the required depth, chain depth remains Unresolved.

### CDC-006
- **Trigger:** a register-launched or primary-input crossing (relation not Same) whose capture chain meets logic (a non-exact Seq edge, including multi-input sequential expressions or combinational intermediates feeding a unique same-domain non-feedback, non-enabled stage before depth 2) between any two consecutive stages; the chain stops there, so stages other than 1 and 2 are checked too.
- **Severity:** as CDC-003.
- **Unknown:** Unknown relation as CDC-003; none otherwise.

### CDC-007
- **Trigger:** a crossing group (relation not Same) or primary input whose chain has a stage short of `CDC-005.min_stages` that drives anything besides the next stage: another register, logic, a top-level output, or a clock or asynchronous-reset use, including capture by a register in another clock domain. With the default of two stages this means the first stage.
- **Exempt:** a stage that has reached `CDC-005.min_stages`. It is an output of the synchroniser, whatever registers follow it, so a pipeline register there and logic beside it are ordinary use.
- **Severity:** as CDC-003.
- **Unknown:** Unknown relation as CDC-003; none otherwise.

### CDC-008
- **Trigger:** a crossing (relation not Same, not a wide symbol) whose capture cone has a non-exact data path from the launch register or primary input through a combinational operator, including a data mux. CDC-028 or CDC-029 assesses the gated data of a procedural enable. The enable signal itself can have a separate crossing.
- **Exempt:** none; relation Exclusive gives INFO instead of WARNING.
- **Severity:** WARNING Established; WARNING Unresolved when Unknown; INFO Informational when Exclusive.
- **Unknown:** a cone through an unmodelled black box also gets CDC-023; wide symbols are classified by CDC-004 only.

### CDC-009
- **Trigger:** a multi-bit crossing group whose destination bits all start chains of depth >= min_stages without link logic and which is neither a Gray pointer, a counter (CDC-017) nor a qualified payload (CDC-039); also exact distinct bits from one source bus into separate scalar chains of depth >= 2 in one destination domain, or multiple launch registers reaching at least two independently synchronized bits of one destination vector. For primary inputs, at least two exact input bits must each reach clean chains of the required depth. Two or more known asynchronous bits establish the finding for that subset even when other bits have different launch relationships.
- **Exempt:** Gray pointers covered by CDC-018, counters (CDC-017), qualified payloads (CDC-039), relation Same. Repeated synchronization of one launch bit is covered by CDC-047.
- **Severity:** WARNING Established, INFO Informational when Exclusive; WARNING Unresolved when Unknown; proof NOT_ATTEMPTED. Exclusive findings carry the trusted SDC declaration.
- **Unknown:** Unknown relation or mixed input relationships without two known asynchronous bits. Separate scalar Gray lanes without a combined CDC-018 timing check retain a WARNING Unresolved obligation and mark `cdc-017` INCOMPLETE. A candidate chain with an opaque stage effect cannot establish a clean lane. The stage uncertainty is disclosed by CDC-003, CDC-004 or CDC-029.

### CDC-010
- **Trigger:** (a) a register d whose fan-in cone holds two or more known or possible asynchronous influences: outputs of recognised synchronisers in d's own domain (also one register stage further), and sources from another domain (relation not Same) that are not gated by a synchronised qualifier; (b) one observed top-level output bit under a valid `set_output_delay -clock C`, whose cone contains two distinct source bits with shared recognised synchronizer provenance and actual combinational logic, with each synchronizer destination related Same to C. Report once per register name/reconvergence kind (grouping multiple registers in the same procedural block that share the exact reconvergence kind, resolution/confidence state, and influence set, listing sorted register names in `signals` and up to 16 `affected_register` evidence entries) or exact output bit/capture clock. Separate output-delay declarations for the same clock do not duplicate an output observation. Output-bit checks use per-bit cones; exact packing, constants, and repeated copies of one source do not qualify.
- **Exempt:** cross-domain sources captured under a synchronised qualifier (CDC-039 pattern) are not counted as raw influences; a same-domain register whose own cone does not directly reconverge at least two synchronised signals and whose influences are already a subset of a single upstream reconvergent register without adding any new influence (pure downstream echo); and, when CDC-039 is enabled, an exact two-element `(1 resolved same-domain synchronised qualifier, 1 same-domain undecided payload)` duplicate on a `(source, destination)` pair already reported by CDC-039. A synchroniser's launch source is resolved rather than marked source-unresolved when its only extra control edges are trusted synchronous resets whose top-level inputs carry valid `set_input_delay` contracts all `Same` to the capture domain and whose data cone has one non-self, non-multi-sequential source with no uncertain leaves.
- **Severity:** WARNING Heuristic for the register-cone predicate; WARNING Unresolved for output-bit reconvergence because source correlation and the external consumer's glitch tolerance are not inferred. Proof NOT_ATTEMPTED for both.
- **Unknown:** WARNING Unresolved when a remaining influence's capture qualification or recognised synchroniser's launch source is undecided. Output-bit detection is limited to enumerated exact bit cones and a declared output capture clock related Same to the synchronizer destination; opaque, unresolved, or differently clocked paths do not establish this predicate and retain CST-012 boundary uncertainty.

### CDC-012
- **Trigger:** a single-bit synchronised crossing (depth >= 2, no link logic) whose synchronizer-stage registers carry ASYNC_REG, sverity_sync or cdc_sync (case-insensitive) on some but not all stages (any profile), or on none of them under profile fpga. A directly adjacent delayed-copy register is excluded only when an exact edge detector is established and every modeled use of that register belongs to the detector. A follower that continues the synchronizer chain, drives a clock or asynchronous control, or has another use remains an attribute stage.
- **Exempt:** no attribute on any stage under the asic or generic profile.
- **Severity:** WARNING Established.
- **Unknown:** if the exact detector or detector-only boundary cannot be established, a direct same-domain follower remains counted as a stage and can produce a conservative mixed-attribute warning. This does not establish that a protocol-history register needs an attribute. Partially marked synchronizer stages remain WARNINGs; only a proven detector-only follower is excluded. Attribute values are read from RTL symbols only.

### CDC-013
- **Trigger:** (a) a single-bit synchronised crossing (depth >= 2, relation not Exclusive) whose periods are not both known, whose source period is < 1.5 x the destination period, or whose source register is computed from logic while both periods are known; (b) an observable synchronised primary input under a matched output-delay capture clock; (c) a configured `boundary_events` contract on a primary input. For (c), prove an unconditional exact input-to-D path into a full synchroniser with a single-edge sampler, a consistent asynchronous launch, and an observable consumer. The first-stage D proof may ignore exactly one asynchronous active-low reset edge only when the model proves one known constant reset value and an exact unconditional released source, and the reset resolves to one unconstrained top-level reset input. The interval comparison on a resettable sampler applies during reset-deasserted operation. The reset input must have no modeled or declared clock role, input-delay contract or applicable or unapplied case value. Use the internal destination period even if no output delay is declared. Each contract names one scalar or simple packed port bit using its RTL index. Its positive finite duration is the minimum asserted interval permitted by the interface, and the checker considers an assertion of that duration. `protocol` records level or event intent. `delivery` determines whether sampling the permitted assertion is required.
- **Exempt:** relation Exclusive for (a); for (b), all active input-delay launch contracts Exclusive to the output clock. The monotonic-level exemption for (a) requires every full-object write to be an exact hold or a same-direction direct `q | independent_expression` or `q & independent_expression` update. Reset, clear, set, partial or unknown writes prevent that exemption. A source register proved constant-stuck at `0` or `1` across every live elaborated nonblocking sequential write (consistent with any async reset and declaration initializer, with optional self-holds and `SelfXor('0')`/`SelfOr`/`SelfAnd` updates from unconditionally constant operands, and no `initial`/`final`, blocking, `iff`, multi-sequential, combinational, or unattributed/called writes) is also exempt from CDC-013, while CDC-003/004/005/006/007/008/026/041 remain active. Reciprocal request/acknowledge synchronizers defer (a) to CDC-024.
- **Severity:** WARNING Established for the register-launched rate case or an applicable required input assertion shorter than one full sampling interval. An event-like register source with known periods and no fast-to-slow ratio trigger is INFO Heuristic. For (c), a best-effort assertion or a required duration at least 1.5 sampling periods on a sampler without reset is INFO Heuristic. A required duration that spans one ideal interval but falls below the 1.5-period review margin is WARNING Unresolved. On a resettable sampler, a required duration that spans the interval remains WARNING Unresolved when the contract cannot establish sampling outside reset. An established internal loss takes precedence over a redundant external delivery warning for the same input and chain. Independent downstream protocol obligations remain open. Proof NOT_ATTEMPTED.
- **Unknown:** WARNING Unresolved for unknown register-launched clock periods, missing external delivery or downstream protocol evidence in (b), and unapplied or ambiguous explicit contracts in (c). Mixed effective input-delay clocks, conflicting clock groups, logic or guards in the input path, unknown periods and unsupported port types do not establish a duration conclusion. Multiple or mixed resets, synchronous reset, unknown/tied-off mode, feedback, enables, masking, multiple writers, or a released source not proven by the exact transition model remain Unresolved. Names and SDC delays cannot establish minimum assertion duration, event spacing or required delivery. Equality and longer duration do not prove distinct delivery, and this check does not prove reset deassertion timing, physical timing, metastability, or protocol correctness.

### CDC-014
- **Trigger:** a single-bit synchronised crossing (depth >= 2) whose source register is a non-monotonic self-dependent state candidate. CDC-013's proved rise-only/fall-only state and provably constant-stuck source registers (see CDC-013) are not treated as active toggles. WARNING when logic lies between the toggle register and the synchroniser, or when no effective edge detector is found. An edge detector uses the same exact bit from a non-first stage and its following stage (directly or through exact combinational aliases on either operand) as the two operands of XOR/XNOR or equality/inequality, or as an AND with exactly one operand inverted. A positive conjunction may qualify an exact comparison, XOR/XNOR, or inverted-AND in registered output data or a branch condition only when its qualifier has no direct or transitive combinational influence from either stage and is not a constant zero or a statically contradictory conjunction (such as `en && !en` or `a & ~a`). A registered direct or inverted-AND detector requires a single surviving complete write outside conditional or loop scopes, or a surviving complete write in the inactive arm of a simple recognized reset with any constant reset write confined to the asserted arm (ignoring earlier unconditionally overwritten dead writes in the same process). A guarded detector requires the two arms of one detector condition to write distinct complete constant results, optionally inside that inactive reset arm. Any registered detector flop (and any destination register along the detector-to-output observation path) must belong to the same destination clock domain and clock edge as the compared synchronizer stages, carry no `iff` qualifier, and force its idle non-event value (`0` for active-high detectors, `1` for active-low detectors, or the non-event arm's constant) on every asynchronous or synchronous reset. Other nested guards, loop scopes, and qualifiers containing calls remain Unresolved. Competing processes, partial/called writes, additional writes, infeasible nested equal/unequal paths, overwritten synchronizer stages or observation registers, and unsupported control-flow/effect cases remain Unresolved. Packed-bit selections count when both select the same proven bit. Nested XOR/OR/negation that can cancel, invert or override an event does not qualify. A comparison branch counts only when its syntax proves that exact pair; matching per-source operator tags or adjacent graph nodes alone do not. Reciprocal request/ack synchronizer legs do not require a standalone edge detector and are handled by CDC-015/024.
- **Severity:** WARNING Established (logic before a structurally recognized toggle); WARNING Unresolved when no edge detector is found because event-toggle intent cannot be distinguished from level or handshake use; INFO Heuristic with a trust model when a detector at or beyond the required depth reaches an output through exact copies, and the required stages, adjacent detector operands, and registered detector/observation flops have compatible clock-domain/edge timing (without `iff`), compatible known asynchronous reset values (forcing idle on detector/observation flops), and compatible values under each shared synchronous reset through the delayed detector stage. Separate source and destination reset signals are assessed by RDC-023. An observed detector on a chain with a stage or detector clock/edge/reset mismatch or unresolved dual-edge timing gives WARNING Unresolved. The detector still carries CDC-024 and any applicable RDC-023 obligations.
- **Unknown:** self-dependent state is a toggle candidate; without an effective edge detector or recognized handshake, RTL does not establish event intent. Distinct packed bits, unrelated comparisons, overwritten/competing writes, stage-dependent qualifiers/guards, conflicting initializers or unestablished guarded-constant toggle operands, and expressions whose outer logic changes event meaning remain WARNING Unresolved. The warning remains at WARNING severity. This is a bounded template proof, not general procedural symbolic execution; branch feasibility and effective values outside these forms are unsupported.

### CDC-015
- **Trigger:** two single-bit synchronised crossings (depth >= 2) between the same two domains in opposite directions, where each distinct source flop reaches an exact stage of the other crossing's synchroniser through combinational next-state dependencies and bounded same-domain state reachability. Elaborated instance hierarchy may differ; hierarchy is retained as provenance and does not block endpoint dependency checks.
- **Exempt:** no pairing across identical source flops, unrelated endpoint cones, same-direction crossings, crossings from provably constant-stuck source flops, or crossings that do not form a unique reciprocal partner. Aliases that resolve to one source flop are not separate legs. Strictly one-way indirect dependencies (`indirect`, neither search-exhausted nor uncertain) whose non-dependent endpoint is a proven asynchronous-reset constant-release bridge (`if (rst) q <= C1; else q <= C2;` with a single async reset, `C1 != C2`, and no data source) are exempt from one-way mismatch warnings; direct one-way dependencies, reciprocal candidates, and uncertain or exhausted searches remain checked.
- **Severity:** INFO Heuristic with a trust model when both legs have one unique reciprocal partner (handshake; the protocol obligation is CDC-024); WARNING Heuristic when only one direction depends on the opposite synchroniser. Ambiguous reciprocal partners are WARNING Unresolved and do not suppress CDC-013/014.
- **Unknown:** dependency is a structural test, not control qualification or protocol proof. Indirect same-domain dependencies can contribute to a pair when the bounded search establishes reciprocal reachability. Unknown cone sources, ambiguous reciprocal partners, and exhausted searches leave the result Unresolved. A separate one-way flag does not displace an exact reciprocal partner, while cross-coupled dependencies between reciprocal candidates make ownership ambiguous. Search is capped at 4,096 visited flops per source and 100,000 visits per analysis (lowerable with `CDC-015.reach_budget` for bounded fixtures); exhaustion marks coverage INCOMPLETE. CDC-013/014 are deferred only for the exact consumed destination chains of a unique reciprocal endpoint pair; additional or ambiguous synchronizer copies keep their hazards. Reset release and functional correctness remain separate obligations.

### CDC-016
- **Trigger:** an unsynchronised multi-bit payload crossing group (width >= 2, depth < 2, no link logic) from domain X to Y in the same destination module instance that also contains a recognised synchroniser (depth >= 2) from X to Y for another source signal, where bounded qualification analysis proves the capture is not qualified by a same-instance synchronized control.
- **Exempt:** payloads qualified by a synchronised control (CDC-039 pattern); a single bit (CDC-003 or CDC-028).
- **Severity:** as CDC-003.
- **Unknown:** Unknown clock relation as CDC-003. Unsupported or undecided qualification shapes (including bounded-expansion cutoffs, case/loop/opaque-call next-state paths, and incoherent bundle qualifiers) are reported under CDC-039 Unresolved with `payload-qualification` INCOMPLETE rather than suppressed. Cross-symbol bundle inference is outside this predicate; individual crossing checks and CDC-039 stability obligations remain active.

### CDC-017
- **Trigger:** a multi-bit crossing group (width >= 2, relation not Same) whose source is a binary counter (cross-bit dependence with a live modeled binary arithmetic `+`/`-` update on the vector), a cross-bit-dependent multi-bit state whose encoding is not proven unit-step, or a Gray-coded pointer (every source bit is a Gray conversion of a counter) with at least one destination bit that is not a clean chain of depth >= min_stages without link logic, early-stage taps, or domain leaks (including a Gray-coded source register split across multiple capture registers in one destination domain when at least one captured bit lacks a clean synchronizer chain). Exact bit aliases through module ports and generate-indexed synchronizer lanes are assembled only when every source bit maps one-to-one into a first-stage capture in one destination clock domain. One generate index may vary while all other path indices and hierarchy remain fixed. Gray conversion aliases are accepted when one exact whole-object assignment, or complete nonoverlapping constant-index split writes from one sequential owner under compatible control, prove the supported adjacent-bit or exact zero-extension form; guarded combinational or latching aliases are not accepted. Gray encoding recognition uses the [shared elaborated branch policy](ANALYSIS.md#prerequisites-of-every-run).
- **Exempt:** Gray pointers whose bits are all synchronised (CDC-018 decides them).
- **Severity:** live binary counter: ERROR Heuristic (Async), INFO Heuristic (Exclusive), WARNING Heuristic otherwise. Cross-bit state without a live modeled binary arithmetic update (e.g. Johnson counter or shift feedback): WARNING Unresolved (INFO Unresolved for Exclusive), proof NOT_ATTEMPTED — never false ERROR from cross-bit dependence alone. Gray not fully synchronised: as CDC-003. An unanalysed source function gives WARNING Unresolved and a proof obligation.
- **Unknown:** counter detection gates ERROR on a live modeled binary arithmetic update; cross-bit state without one stays WARNING Unresolved. Unknown relation gives WARNING Unresolved for the Gray case. User-function output remains unresolved unless its single pure body is proved to implement the supported Gray conversion. Competing partial writes, opaque calls, competing whole writes, guarded alias writes, or unresolved alias configurations prevent Gray classification. Incomplete or duplicated generated-lane mappings of a multi-bit source produce CDC-009 WARNING Unresolved and mark `cdc-017` INCOMPLETE. More than one varying generate index, complementary source ranges under separate loops, opaque aliases, and unsupported converter expressions do not establish Gray; scope is INCOMPLETE where the model records the precision loss. Destination first-stage constant overrides count as reset candidates only when all effective forcing writes are constant, each affected bit has one exact normal D write, guard polarity and forced value agree across priorities, every guard is trusted in the destination domain (or is a primary-input reset candidate), and every affected sibling has the same guard/polarity/value set. A proven unconditional constant override suppresses the stage. A source-domain guard remains a crossing hazard. Unequal sibling guard sets leave CDC-018 WARNING Unresolved with a reset-coherency obligation; they do not establish a safe Gray crossing.

### CDC-018
- **Trigger:** a Gray-coded crossing (CDC-017 detection) whose destination bits all start chains of depth >= min_stages without link logic. INFO requires direct unit-step source evidence: a full binary register vector with one sequential owner and direct unnarrowed plus-one or minus-one updates, optionally held by an enable or explicit self-hold (`bin <= bin`), and pure non-compound recognized asynchronous reset writes. The Gray register must directly convert the unnarrowed binary vector (no arbitrary intermediate expressions or extra cone leaves) and sample it on the same clock and edge without an additional enable or event `iff` qualifier. If reset is present, both registers must share one normalized asynchronous reset and the Gray reset value must encode the binary reset value. All destination Gray siblings must share the same capture clock edge, matching synchronous and asynchronous reset signatures, and clean synchroniser chains (no stage clock/reset mismatch, tap, or domain leak). A constraint is established only when supported `set_units -time` explicitly establishes units for both the active source clock and the delay, numeric unqualified `set_max_delay -datapath_only` (without `-reset_path`, `-hold`, or edge qualifiers) endpoint constraints cover every source-bit/first-stage path using declared RTL bit indices, and each delay is no greater than the active source period. A clock group separation (including overlapping wildcard or `-regexp` groups) or a potentially overlapping false path (including bare clock names and hierarchical `[get_cells]` selectors) prevents trusting the max-delay. Every potentially competing matched max-delay must satisfy the same checks. Unreadable `--sdc` files, parse-rejected timing/clock/unit commands, and any unsupported SDC commands leave the bound Unresolved. A max-delay by itself does not establish the clock relationship.
- **Exempt:** none. Missing, partial, through-only, unqualified, unit-unknown, `-reset_path`, `-hold`, oversized or otherwise unsupported constraints do not discharge the obligation, including for Exclusive clock relationships.
- **Severity:** WARNING Unresolved, proof NOT_ATTEMPTED, unless both the direct transition evidence and the complete bound above are established. INFO Heuristic with a trust model when it is established; the timing constraint is trusted and the Gray/FIFO functional properties are not proven.
- **Unknown:** unsupported units, unit-unknown clock periods, unknown source period, endpoint coverage that cannot be matched against declared RTL bit indices, inconsistent reset guards/async resets or capture clock edges across destination Gray siblings, or malformed destination synchroniser chains produces WARNING Unresolved. Multiple active clock names on either crossing root also produce WARNING Unresolved and mark constraints coverage INCOMPLETE. Unsupported source updates or sampling cadence remain Unresolved. The evidence scan is limited to 4,096 source bits and 100,000 procedural writes. Reset coherency, bus skew and physical timing remain open.

### CDC-019
- **Trigger:** (a) a clock domain whose root is a logic net whose combinational cone reaches two or more clock leaves (clock roots, SDC-declared ports, top-level inputs named clk or clock, or structurally evidenced self-inverting divided-clock operands); (b) a top-level output named as a clock whose combinational cone reaches two or more identified clock leaves, even when no register consumes the output in this elaboration.
- **Exempt:** none; no glitch-free clock mux cell is recognised.
- **Severity:** WARNING Unresolved.
- **Unknown:** always WARNING Unresolved; scope clock-extraction INCOMPLETE. A register is treated as a divided-clock operand only when its sole exact procedural write is an unconditional self-inversion and it reaches a mux data arm or a gate cone without another identified clock; this identifies an operand, not a generated-clock phase relationship.

### CDC-020
- **Trigger:** a clock gated by combinational logic (exactly one clock operand, enable from registers or inputs) whose enable register is in a domain whose relation to the operand's source clock is not Same, or whose enable is a primary input, or whose enable register has no identified clock; also a library clock_gate instance whose enable comes from a register in another domain than its clock. A structurally evidenced divided-clock operand uses its launching clock only for this comparison.
- **Exempt:** enable registers in a Same domain. Latch-based gates are not exempt here (see CDC-045).
- **Severity:** ERROR Established (Async); INFO Informational (Exclusive); WARNING Established (other known relation); WARNING Unresolved (Unknown, primary-input enable, unidentified enable or clock).
- **Unknown:** primary-input enable and unidentified enable or clock give WARNING Unresolved; a clock cone through an unmodelled black box also gets CDC-002.

### CDC-023
- **Trigger:** a register bit whose fan-in cone reaches a net connected to an unmodelled black box (undeclared instance, all connected nets) or to an output of a declared --library black box. Library RAM read data is not included.
- **Severity:** WARNING Unresolved, one per capturing signal.
- **Unknown:** scope blackboxes INCOMPLETE; whether the path crosses a clock domain stays unresolved.

### CDC-024
- **Trigger:** one obligation per recognized structural candidate: a uniquely coupled pair of opposite-direction Gray crossings (CDC-034), an incomplete one-way, partial, ambiguous, or search-limited Gray-pointer coupling, a handshake (CDC-015 with unique reciprocal endpoint dependence) or a toggle (CDC-014 with an edge detector) that is not a leg of a recognized handshake. A two-phase handshake is one structure; its obligation lists the toggles it covers. Ambiguous handshake endpoint pairings receive an Unresolved obligation only when reciprocal dependence is observed; a generic obligation is not evidence of an unrelated functional defect.
- **Severity:** WARNING Heuristic for a complete unique structural candidate, proof NOT_ATTEMPTED; WARNING Unresolved for incomplete, ambiguous, or search-limited candidates, proof NOT_ATTEMPTED.
- **Unknown:** never reported as verified. Unrelated opposite-direction streams produce no FIFO or handshake obligation. Shared flow that leaves multiple pairings possible remains Unresolved and does not establish a pair.

### CDC-026
- **Trigger:** a register crossing or asynchronous primary-input chain whose required stages differ from the previous stage in clock edge, or whose stages have different asynchronous reset sources or effective assertion polarities. Exact inverted aliases of one reset are normalized together. Only stages through `CDC-005.min_stages` are compared: a register after them is not part of the synchroniser. A primary-input mismatch also prevents CDC-029 from calling the chain clean containment or using its output as clean qualifier evidence.
- **Severity:** as CDC-003.
- **Unknown:** Unknown relation as CDC-003; unresolved alias logic is kept distinct rather than treated as an equivalent reset.

### CDC-028
- **Trigger:** a crossing group with at least one destination bit that is unsynchronised and unqualified (depth < 2, no link logic) whose capture register has a clock-enable (control) input.
- **Guard analysis:** exact single-bit equality or inequality can expose a raw cross-domain enable. Qualification is evaluated per capture bit across every modeled write (including per-bit decomposed ternary muxes and bounded staged combinational next-state logic from `always_comb`/`assign`) that samples the same register launch domain or named primary input, and checked for common qualifier and polarity coherence across multi-bit bundles. Writes and mux arms whose data depends only on destination-domain state or constants do not count as crossing writes; one synchronized control at one polarity must be necessary on all remaining writes and shared across the bundle. A bypass, raw cross-domain default, trailing overwrite, or raw cross-domain read in a non-qualifying mux arm is unsafe. So are complementary writes whose sole necessary qualifier is used at opposite polarities. Distinct necessary controls without a proven bypass and incoherent bundle qualifiers remain Unresolved. Unsupported or approximate source dependencies remain subject to the CDC-039 uncertainty policy.
- **Exempt:** qualified payloads and undecided capture qualification (CDC-039).
- **Severity:** as CDC-003.
- **Unknown:** Unknown relation as CDC-003; undecided capture-control necessity is reported by CDC-039.

### CDC-029
- **Trigger:** (a) a top-level input bit captured by registers of clock domain D; (b) a primary-input feed-through to a top-level output with `set_output_delay -clock C`, where no matching `set_input_delay -clock L` establishes relation Same between L and C. A capture is declared synchronous when an active `set_input_delay` contract names a clock related Same to D; recognised when every capturing register starts a chain of depth >= 2 without link logic. Chains below the configured minimum depth retain a separate CDC-005 finding.
- **Exempt:** none. A declared synchronous input is INFO and skips the structure checks below.
- **Severity:** For register captures, ERROR Established when an active input-delay contract establishes an asynchronous launch and at least one individual unsynchronised capture has a precise input-to-D dependency with no unresolved alternate path that could mask it; a recognised synchronised payload qualifier exempts that data capture from this ERROR and instead creates a CDC-039 stability obligation. For a primary-input qualifier, its effective input-delay contract must establish the same launch clock as the payload. A register-launched qualifier uses its modeled launch clock. Unknown qualifier provenance remains Unresolved when the guard requires that qualifier; a proven Boolean bypass can still establish unsafe capture. Each opaque, approximate, or otherwise uncertain sibling capture remains a separate WARNING Unresolved, even when another capture establishes ERROR. If no capture establishes unsafe sampling, an uncertain unsynchronised capture is WARNING Unresolved. INFO Heuristic for declared-synchronous or structurally synchronised captures, and for captures under a recognised qualifier (with CDC-039 obligation). For output feed-through, an asynchronous input-delay relationship is ERROR Established; without an established same-clock launch contract it is WARNING Unresolved.
- **Unknown:** an opaque call, approximate/conservative graph edge, precision fallback, undecided qualifier, or a mux whose non-hold arm may sample data cannot establish unsafe sampling; retain WARNING Unresolved and mark graph-precision/payload-qualification INCOMPLETE. A ternary feedback arm is treated as a hold only when the single exact write has a direct `q` feedback data arm; feedback through logic such as `q ^ data` remains a data-sampling path. Input dependencies are checked per capture using graph data/control edges: an asynchronous input sampled as a control is still an unsafe control capture unless contained by its own recognised synchroniser. A data input used under a recognised synchronised control is a payload transfer, not evidence of metastability containment for the payload; CDC-039 records source stability/protocol obligations. No matching set_input_delay and no recognised synchroniser gives WARNING Unresolved; on such an input CDC-006, CDC-007, CDC-008, CDC-009 and CDC-010 are also evaluated as for a register crossing. Effective input-delay contracts are resolved per bit and independently for min/max; `-add_delay` retains the applicable launch contract, while a later non-add clause replaces only its mode. An output delay names the capture clock but does not establish the primary input's launch clock. An established asynchronous data contract can still prove an unconditional unsafe capture when another mode is unknown, but unknown/mixed launch possibilities cannot prove same-source qualification. A recognized qualifier with absent or partly unknown launch provenance is Unresolved, not a same-source result. A recognized synchroniser remains a structural containment result with source stability and pulse-width obligations; protocol correctness is not inferred.

### CDC-030
- **Trigger:** each clock domain whose SDC clock is declared with create_generated_clock.
- **Severity:** WARNING Unresolved.
- **Unknown:** crossings between the generated clock and its master stay UNKNOWN until a clock group relates them; scope clock-relationships INCOMPLETE.

### CDC-031
- **Trigger:** a clock mux (CDC-019 shape, two or more clock leaves) where a select register is not in the Same domain as a switched clock, a select has no identified clock, a select is a primary input, or the output clock's relation to a leaf is Unknown.
- **Severity:** WARNING Unresolved.
- **Unknown:** the unknown-relation case is itself a finding; scope clock-extraction INCOMPLETE (as CDC-019).

### CDC-032
- **Trigger:** (a) a multi-bit crossing group whose destination bits have chains of different depth (depth >= 2, no link logic), or some bits chain-synchronised and some not; (b) one source signal captured into separate destination chains with different depths, including distinct bits split across instances or repeated captures of one bit (a link-logic bit counts as depth 1). Pairing is based on modeled source-bit dependencies, not instance-name similarity.
- **Severity:** (a) as CDC-003; (b) ERROR Established when Async, INFO when Exclusive, otherwise WARNING Established.
- **Unknown:** Unknown relation gives Unresolved confidence (WARNING).

### CDC-034
- **Trigger:** two complete Gray-coded crossing buses (CDC-017 detection, including complete nonoverlapping constant-index split non-reset Gray writes from one sequential owner under compatible control) in opposite directions between the same two domains. Every source pointer bit must depend on at least one opposing first-stage bit, every opposing first-stage bit must affect the source pointer, and each bus must have exactly one possible partner.
- **Severity:** WARNING Heuristic when any observed bit of a pointer register or its modeled next-state fan-in register has no effective constant asynchronous reset write (`'0'` or `'1'`), including partial-bit reset branches that omit a bit. INFO Heuristic when every observed bit of those registers has a resolved constant asynchronous reset write. Synchronizer stages are outside this check. Grading is structural and applies to Async, Exclusive and Unknown clock relations.
- **Unknown:** A non-constant or self-holding asynchronous reset branch, or a tied or unresolved asynchronous reset source, produces WARNING Unresolved and marks reset-extraction INCOMPLETE. One-way, partial, ambiguous or search-limited dependence produces WARNING Unresolved CDC-024 and RDC-023 obligations. CDC-034 also reports WARNING Unresolved when such a candidate has a missing or unresolved pointer reset. No dependency produces no FIFO finding. A complete unique structural candidate does not prove semantic pointer pairing, full/empty arithmetic, storage, or read/write control; CDC-024 records that obligation. Pointer reset-release coordination is RDC-023.

### CDC-035
- **Trigger:** (a) a crossing group (relation not Same) whose source or destination signal is an unpacked-array memory, wide memories included; (b) a library RAM (--library kind ram) whose write clock domain and read clock domain differ with relation not Same; (c) each port of a library RAM with a data-in, write-enable, address or data-out role and with nodes: an input port whose fan-in cone reaches registers or primary inputs, and a data-out port whose value is captured by registers through combinational logic. Each register crossing is checked between its own domain and the port's reference clock domain: the domain of the clock port named by the port's library `clock` field; without that field, data-in and write-enable use the write clock, data-out uses the read clock, and an address port has none. For (c), suppress the unsynchronised read-port finding only for a direct RAM bit capture at the head of a clean receiving-domain chain that meets the configured minimum depth. Independent clean chains for distinct bits of one read port in the same asynchronous receiving domain retain a bus-coherence review obligation. An asynchronous write-data crossing has a Heuristic qualification obligation when the sole scalar write-enable input uses the write clock and connects by an identifier that names or exactly aliases a complete synchroniser output from the data launch domain. Short taps, a single direct scalar conjunction with a matching synchronized dependency, and ambiguous enables whose modeled dependencies all match retain an Unresolved qualification obligation. Other unsupported shapes can retain the ordinary asynchronous port ERROR. An empty non-clock port preserves the RAM model and the checks on other ports.
- **Exempt:** relation Same (no finding); relation Exclusive gives INFO.
- **Severity:** (a), (b): WARNING Unresolved (proof NOT_ATTEMPTED), any relation other than Exclusive; INFO Unresolved when Exclusive. (c): per register crossing ERROR Established when Async, INFO Established when Exclusive, WARNING Established otherwise, WARNING Unresolved when the relation is Unknown. An asynchronous port crossing with a recognised synchronised qualifier is WARNING Heuristic (proof NOT_ATTEMPTED). A primary input in a port cone, an unidentified register clock, or a missing port reference clock is WARNING Unresolved.
- **Unknown:** library RAM with a write or read clock that does not resolve, including an unconnected or tied-constant clock: WARNING Unresolved, scope clock-extraction INCOMPLETE; (c) an unresolved qualifier is WARNING Unresolved, scope payload-qualification INCOMPLETE. An unresolved reference or register clock is WARNING Unresolved, scope clock-extraction INCOMPLETE; a primary input in a port cone: WARNING Unresolved, scope constraints INCOMPLETE; an unknown clock relationship remains Unresolved even when a clean read chain exists. Vendor read-during-write semantics, bus coherence and payload stability are not proved.

### CDC-037
- **Trigger:** (a) a crossing group whose clocks are declared exclusive (set_clock_groups -logically_exclusive or -physically_exclusive) and whose destination starts a chain of depth >= 2; (b) two distinct clock roots that SDC gives the same clock name, so paths between them are treated as synchronous.
- **Severity:** (a) WARNING Established; (b) WARNING Unresolved.
- **Unknown:** (b) scope clock-relationships INCOMPLETE.

### CDC-038
- **Trigger:** a crossing group (relation not Same) covered by an SDC set_false_path or set_multicycle_path whose -from and -to match the source and destination registers (a -through-only exception matches on its -through names).
- **Exempt:** set_max_delay and set_min_delay exceptions (the path stays timed).
- **Severity:** WARNING Established; the message states whether a synchroniser is present.
- **Unknown:** -through is not path-evaluated: when -from or -to is present it is ignored, so the match uses -from and -to names only. `-regexp` selectors are retained but not interpreted; their possible coverage is disclosed as INCOMPLETE constraint analysis.

### CDC-039
- **Trigger:** an unsynchronised payload crossing or asynchronous top-level input capture whose qualification is either proven necessary or undecided. Proven necessary means every data-moving write (including decomposed ternary muxes and bounded staged `always_comb`/`assign` next-state logic) that samples the same launch domain at a register capture bit, or samples the same primary input bit, requires the same control synchronized from the established launch domain into the capture domain at the same polarity, and all qualified bits of a multi-bit bundle share a single synchronized qualifier and effective polarity; local conjunctions may restrict capture further and non-qualifying arms that depend solely on destination-domain state or constants do not count as crossing writes. A concrete bypass or absence of matching control is instead reported by CDC-003/004 and CDC-028. A primary input under a recognized qualifier retains an explicit source-stability/timing obligation. A chain with multiple source bits, an incomplete source cone, or an unknown primary-input launch clock cannot establish same-source qualification.
- **Severity:** WARNING Heuristic for proven necessity, retaining the unproved stability/timing obligation. WARNING Unresolved for undecided necessity or incoherent bundle qualifiers. Both carry proof NOT_ATTEMPTED.
- **Unknown:** state-held validity, a qualifying chain shorter than the required depth, opaque calls, unsupported Boolean semantics, cyclic logic, approximate source dependencies, `case` statements or un-unrolled loops in next-state logic, incomplete/multi-driver combinational next-state blocks, or proof/walk/expansion limits (16 arms per bit, depth 8, 64 expanded writes) prevent a necessity claim; distinct necessary controls on separate source writes and distinct qualifiers or opposite polarities across bits of a multi-bit bundle are also Unresolved absent a proven bypass. The path stays visible with an explicit proof obligation and INCOMPLETE scope. Neither result proves data stability or protocol intent.

### CDC-040
- **Trigger:** (a) a module annotated (* sverity_sync *) or (* cdc_sync *), checked for a recognised synchroniser (depth >= 2) inside its instance path; (b) every declared --library cell instance of kind synchronizer, reported with its stage count (flop, clock_gate, ram and blackbox cells are described by their own rules).
- **Severity:** (a) WARNING Established when no recognised synchroniser is inside, INFO Heuristic when one is (proof NOT_ATTEMPTED); (b) INFO Heuristic, proof NOT_ATTEMPTED.
- **Unknown:** a malformed --library file or cell entry gives CST-018 ERROR and the cell is not registered, so its instance is walked as an ordinary module; library declarations are trusted, not verified.

### CDC-041
- **Trigger:** a synchronised crossing (single-bit with depth >= 2, or multi-bit whose first destination bit starts a chain of depth >= 2 without link logic; not a memory) whose paired source register and synchroniser output stage (the stage reaching the required depth, not a follower) have different asynchronous reset sources or effective assertion polarities, or whose paired source is reset and the last stage is not.
- **Exempt:** same-reset pairs; and, when RDC-023 is enabled, per-leg independent-reset findings for clean-reset synchroniser legs (no stage reset mismatch) of uniquely recognised handshakes and uniquely paired independently-reset Gray FIFOs, which are reported jointly under RDC-023. Legs with stage reset mismatches, unpaired crossings, and runs with RDC-023 disabled retain CDC-041.
- **Severity:** WARNING Heuristic for different reset roots (proof NOT_ATTEMPTED); INFO Heuristic for a source-only reset.
- **Unknown:** heuristic: exact inverted asynchronous reset aliases are normalized by effective assertion polarity and source endpoint, and bus checks use actual source/capture bit pairs. Reset values, reset-release timing and protocol correctness are not proved; ambiguous endpoint mapping remains outside this predicate.

### CDC-043
- **Trigger:** (a) a register-to-register path inside one clock domain (through the fan-in cone) between a register on one clock edge and a register on the opposite edge; (b) a register triggered on both clock edges.
- **Severity:** (a) WARNING Heuristic; (b) WARNING Unresolved.
- **Unknown:** (b) dual-edge behaviour is not modelled; scope clock-relationships INCOMPLETE. A required dual-edge stage cannot establish synchroniser containment or payload qualification.

### CDC-044
- **Trigger:** a top-level input bit (declared or not) whose capturing registers all start chains of depth >= 2 without link logic, and a synchronized chain has either (a) two adjacent stages that both contribute through data or control to one scalar consumer, even when other stages also contribute, or (b) at least two distinct effective cycle depths of the chain connected through exact aliases to distinct bit positions of the same top-level output port, directly (cycle depth `d` of stage `d`) or through one unconditional exact same-domain capture (cycle depth `d + 1`), including mixed direct and one-hop observations with distinct effective cycle depths. Unconditionally overwritten dead writes, multi-driver/constant-overwritten captures, literal-zero masked expressions, and self-canceling constant comparisons do not establish stages, consumers, or shift-word mappings. Reset-qualified (asynchronous or synchronous), enabled, `iff`-qualified, blocking, or dual-edge one-hop captures are not unconditional and do not establish the shift-word predicate. The adjacent-stage condition is review evidence only; it does not prove a precise edge detector or CDC-014. Approximate/opaque paths do not establish either predicate. Repeated aliases of one stage (including mixed taps that observe the same effective cycle depth, such as `word[0] <= s2` and `word[1] = s3`) count once. Processed output bits do not establish the shift-word predicate. A scalar level use, including a deep delay line, is not stream evidence. Chain depth alone is not evidence of serial/event intent. Skip this rule only when every effective input launch relation is established Same or Exclusive; Async, Unknown, undeclared, and mixed modes remain eligible.
- **Severity:** WARNING Heuristic with proof NOT_ATTEMPTED. The structure signals possible event/serial use; the warning is an explicit review obligation, not a proof of unsafe oversampling. Positive sibling chains share one finding per input/domain; deterministic evidence is capped at 16 chains, 16 consumers and 16 shift-word mappings. Once a seventeenth positive sibling is established, later siblings are not analyzed and the report discloses a lower bound rather than an exact omitted count.
- **Unknown:** when output-bit precision, alias propagation or the stage-to-consumer relation is uncertain, no corresponding predicate is established. The shared adjacent-stage search has a one-million-node work budget per analysis; exhaustion emits WARNING Unresolved and marks graph-precision coverage INCOMPLETE. A positive witness found before exhaustion remains reported, while unsearched chains are explicitly unresolved. Evidence-only output reconvergence does not prove a precise edge detector. A runtime-selected latency tap can conservatively trigger when adjacent stage values reach the same scalar mux output; this is a known false-positive limit because the analysis does not prove the mux is only selecting a stable level. Clock and asynchronous-reset consumers remain subject to their clock/reset hazards and do not count as serial protocol evidence. Existing CDC-007 early-tap and CDC-013/boundary-event conclusions remain independent and are not discharged by this rule. No spacing or rate is inferred from synchronizer depth.

### CDC-045
- **Trigger:** (a) a clock gated by combinational logic (one clock operand) whose enable reaches the gate from a register or a primary input, with no latch that is transparent while that same clock is low and whose output reaches the gate only through a positive AND path; (b) a library clock_gate whose declaration has enable_latched false; (c) a clock gated through such a latch, or a library clock_gate with enable_latched true.
- **Exempt:** latch-based gates (c) are INFO, not findings.
- **Severity:** (a) WARNING Heuristic; (b) WARNING Established; (c) INFO Heuristic with a trust model (the latch pattern is recognised; its phase and timing are not verified).
- **Unknown:** a primary-input enable is also reported by CDC-020 (WARNING Unresolved). Latch matching uses elaborated signal identity through aliases; unrelated clock latches and OR/inverted gate forms do not qualify. If hierarchy, port transfer, or source syntax prevents proving the latch-to-clock path, the latch is not accepted and CDC-045 remains a conservative warning.

### CDC-046
- **Trigger:** (a) declared box (--library kind blackbox): each input port (not an output, clock or reset port) whose fan-in cone reaches registers or primary inputs, checked against its reference clock: the clock port named by the port's library `clock` field, else the box's only clock port; with several clock ports and no association the reference is unresolved. Each register whose domain has a relation to the reference other than Same is a crossing. (b) undeclared box: every connected net; a cone spanning two or more source domains, or clocks of two or more domains or SDC clocks whose relation is not Same entering the box, where a crossing inside it is not analysed. In both forms an input from a register with an unidentified clock always reports.
- **Exempt:** sources in the reference domain; relation Same; single-domain inputs of an undeclared box.
- **Severity:** (a) ERROR Established (Async), INFO Established (Exclusive), WARNING Established (other known relation) per crossing; WARNING Unresolved for an Unknown relation, an unresolved reference clock, an unidentified source clock, and a primary input. (b) WARNING Unresolved.
- **Unknown:** an undeclared box fed from one domain gets no CDC-046 (its nets are covered by CDC-023); an unresolved reference clock or a multi-domain undeclared box marks scope blackboxes INCOMPLETE; an unidentified source clock marks clock-extraction INCOMPLETE; a primary input marks constraints INCOMPLETE.

### CDC-047
- **Trigger:** one register bit or primary input bit with recognised chains (depth >= 2, no link logic) into two or more distinct destination bit captures in one clock domain; one per launch bit and set of destinations. Vector bits remain distinct captures even when they share a packed destination symbol. For a primary input, effective `set_input_delay -clock` clauses are considered per min/max mode; `-add_delay` retains prior launch contracts. Any asynchronous launch remains relevant; other mixed relationships stay Unknown.
- **Exempt:** chains in different destination domains; one chain whose last stage fans out; a wide symbol (CDC-004 or CDC-035).
- **Severity:** WARNING Heuristic, proof NOT_ATTEMPTED; INFO when the clocks are declared exclusive, with an explicit trust_model that exclusivity is trusted rather than verified.
- **Unknown:** Unknown relation gives WARNING Unresolved. For an input with no matching `set_input_delay`, constraints coverage is also INCOMPLETE. Whether logic combines the copies is not established: the finding is the structure, not the glitch.
